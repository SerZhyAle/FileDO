## Быстрый старт

### Наиболее частые задачи

```bash
# Проверить поддельность USB/SD карты
filedo E: test del

# Тест производительности диска
filedo C: speed 100

# Безопасная очистка свободного места
filedo D: fill 1000 del

# Поиск и управление дубликатами файлов
filedo C: check-duplicates
filedo D:\Photos cd old del

# Копирование с прогрессом
filedo folder C:\Source copy D:\Backup
filedo device E: copy F:\Archive
# Сначала сосчитать дерево ради точного оставшегося времени (иначе копирование начинается с первого файла)
filedo folder C:\Source copy D:\Backup --precount

# Быстрая очистка папок
filedo folder C:\Temp wipe
filedo folder D:\Cache w

# Показать информацию о диске
filedo C: info
```

### Сравнение папок и очистка

`compare <source> <target> --strict` проверяет совпадение деревьев: одинаковые относительные пути, размеры и время изменения дают `Passed` (код 0); различие даёт `Failed` (код 1); неполное сравнение даёт `Not proven` (код 2). Добавьте `--by-hash`, чтобы сравнивать пары одинакового размера по содержимому вместо времени. Обычный `compare` по-прежнему сообщает различия с `Done` (код 0); `--strict` нельзя совмещать с удалением. Оба режима передают `onlyInSource`, `onlyInTarget`, `differentFiles`, `sameFiles`, `totalSource` и `totalTarget` в результате `--events`. Для `check` ограничение `--max-files N` допускает чтение не более N файлов (0 снимает ограничение); `--resume` завершается с `Passed` (код 0), когда каждый подходящий файл имеет неизменившуюся запись в хорошем списке: `checkedFiles = 0`, а `skippedGoodFiles` показывает ранее проверенные файлы.

```bash
# Сравнить две папки и сохранить отчёт
filedo compare D:\Data E:\Backup

# Сравнить и удалить (перманентно, без подтверждения)
filedo cmp D:\Data E:\Backup del source  # удалить в Source, если есть в Target
filedo cmp D:\Data E:\Backup del target  # удалить в Target, если есть в Source
filedo cmp D:\Data E:\Backup del old     # удалить более старый (mtime), равные: пропуск
filedo cmp D:\Data E:\Backup del new     # удалить более новый (mtime), равные: пропуск
filedo cmp D:\Data E:\Backup del small   # удалить меньший, равные: пропуск
filedo cmp D:\Data E:\Backup del big     # удалить больший, равные: пропуск
 
# Необязательная сторона (ограничение по стороне)
filedo cmp D:\Data E:\Backup del small source  # только если меньший на Source
filedo cmp D:\Data E:\Backup del big target    # только если больший на Target
filedo cmp D:\Data E:\Backup del old target    # только если старший на Target
filedo cmp D:\Data E:\Backup del new source    # только если новейший на Source
filedo cmp D:\Data E:\Backup del source --yes  # без вопроса (скрипты); проверки остаются
```

Примечания: сопоставление по относительному пути; `del source` и `del target` удаляют пару, только если совпадают размер и время изменения (`--by-hash` - совпадает содержимое; `--allow-mismatch` - любую пару), а несовпавшая пара выводится и остаётся; два написания одной папки или папка внутри другой отклоняются; каждое правило удаления сначала показывает, сколько файлов и по какому режиму будет удалено, и спрашивает `(y/N)` - `--yes` (или `-y`) пропускает вопрос, но не проверки, а без ответа (закрытый stdin, скрипт) ничего не удаляется и код выхода 2; mtime для old/new; Windows - без учёта регистра, а удаление идёт по настоящему имени файла; если что-то не удалось прочитать или удалить, код выхода 2; логи: compare_report_*.log, delete_report_<mode>_*.log.

### CHECK - быстрая проверка чтения

```bash
# Проверка папки: читаем файлы; если задержка первого чтения > 2.0с - файл помечается как повреждённый
filedo check F:\Mov
```

- Однократный «прогрев» до 10.0с перед первым чтением (пробуждение HDD)
- Списки повреждённых и «хороших» файлов лежат в `%LOCALAPPDATA%\FileDO\state` (никогда не рядом с вашими файлами) и называют файл путём, размером, временем изменения, томом и самим файлом, на котором он был записан - изменённый файл или копия по тому же пути на другой карте под той же буквой диска читается снова; записи старых версий без тома не принимаются на веру; у copy свой, отдельный список пропуска
- Файл из списка повреждённых снова считается повреждённым без повторного чтения (код 1); заблокированный или нечитаемый файл или папка - «не удалось проверить» (код 2), а не «повреждён»
- Файл «только в сети» (заглушка OneDrive или другого облака, либо файл offline) никогда не открывается - ни при обходе, ни когда проверяется именно он, - поэтому ничего не скачивается. Он считается как `not-read(online-only)`, никогда не записывается в повреждённые и делает запуск «не удалось проверить» (код 2), если не найден повреждённый файл (код 1)
- Параллельные воркеры; поддержка Ctrl+C

#### Флаги CHECK (флаги имеют приоритет над переменными окружения)

Флаги дублируют FILEDO_CHECK_* и удобны для интерактивного запуска.

- Общие
	- `--threshold <sec>` (FILEDO_CHECK_THRESHOLD_SECONDS)
	- `--warmup <sec>` (FILEDO_CHECK_WARMUP_SECONDS)
	- `--warmup-idle <sec>` (FILEDO_CHECK_WARMUP_IDLE_RESET_SECONDS)
	- `--workers <int>` (FILEDO_CHECK_WORKERS)
	- `--buf-kb <int>` (FILEDO_CHECK_BUF_KB)
	- `--mode quick|balanced|deep` (FILEDO_CHECK_MODE)
	- `--balanced-min-mb <int>` (FILEDO_CHECK_BALANCED_MIN_MB)
	- `--min-mb <float>` / `--max-mb <float>` (FILEDO_CHECK_MIN_MB / FILEDO_CHECK_MAX_MB)
	- `--include-ext ".jpg,.png"` / `--exclude-ext ".bak,.tmp"` (FILEDO_CHECK_INCLUDE_EXT / FILEDO_CHECK_EXCLUDE_EXT)
- Ограничения
	- `--max-files <int>` (FILEDO_CHECK_MAX_FILES)
	- `--max-seconds <float>` (FILEDO_CHECK_MAX_DURATION_SEC)
	- `--precount` / `--no-precount` (FILEDO_CHECK_PRECOUNT)
- Поведение и вывод
	- `--dry-run` (FILEDO_CHECK_DRYRUN)
	- `--verbose` (FILEDO_CHECK_VERBOSE)
	- `--quiet` (FILEDO_CHECK_QUIET)
	- `--resume` (FILEDO_CHECK_RESUME) - продолжить: пропустить файлы, которые прошлый запуск уже прочитал без ошибок («хороший» список)
- Отчёты
	- `--report csv|json` (FILEDO_CHECK_REPORT)
	- `--report-file <path>` (FILEDO_CHECK_REPORT_FILE)
- Кэш «хороших» файлов
	- `--good-list <path>` (FILEDO_CHECK_GOODLIST)
- Режим single-reader и адаптивная пауза (для HDD/USB)
	- `--single-reader auto|on|off` (FILEDO_CHECK_SINGLE_READER)
	- `--ewma-alpha <float>` (FILEDO_CHECK_EWMA_ALPHA)
	- `--ewma-high-frac <float>` (FILEDO_CHECK_EWMA_HIGH_FRAC)
	- `--ewma-low-frac <float>` (FILEDO_CHECK_EWMA_LOW_FRAC)
	- `--max-sleep-ms <int>` (FILEDO_CHECK_MAX_SLEEP_MS)
	- `--sleep-step-ms <int>` (FILEDO_CHECK_SLEEP_STEP_MS)
	- `--hdd-sleep-ms <int>` (FILEDO_CHECK_HDD_SLEEP_MS) - постоянная пауза после каждого файла, у каждого читателя

Примеры:

```bash
# Balanced-режим, фикс кол-ва потоков, подсчёт для стабильной ETA
filedo check D:\Data --mode balanced --workers 6 --threshold 1.8 --precount

# Принудительно один читатель + адаптивная пауза по EWMA
filedo check F:\Photos --single-reader on --ewma-alpha 0.2 --max-sleep-ms 250

# Фильтрация по расширениям, лимит по кол-ву и CSV-отчёт
filedo check D:\Media --include-ext .jpg,.png --max-files 1000 --report csv --report-file D:\rep.csv

# Свой список «хороших» файлов и тихий вывод
filedo check D:\Data --good-list D:\check_files.list --quiet
```

### Установка

#### Вариант 1 - winget (рекомендуется)

```powershell
winget install SerZhyAle.FileDO
```

Ставит инструменты командной строки (`filedo`, `filedo_check`, `filedo_fill`, `filedo_test`) и графическое окно `filedo_win` (страница на каждое задание), и добавляет их в `PATH`.

Также есть в [Microsoft Store](https://apps.microsoft.com/detail/9PH1LPCMRG83) - те же инструменты, установку и обновления берёт на себя Store.

#### Вариант 2 - Установщик (setup EXE)

Скачайте `FileDO-<версия>-setup.exe` из [релизов](https://github.com/SerZhyAle/FileDO/releases/latest) и запустите. Именно этот вариант делает FileDO обычной программой Windows, а не папкой с исполняемыми файлами:

- ставит файлы в `C:\Program Files\FileDO` и добавляет `filedo` в системный `PATH`;
- создаёт **пункт в меню «Пуск»** и **значок на рабочем столе** для окна FileDO (`filedo_win.exe`) и второй пункт в меню «Пуск», **FileDO Disk Manager**, который сразу открывает Диспетчер дисков (`filedo_win.exe --disks`);
- регистрирует **интеграцию с Проводником**: группу `File DO..` в контекстном меню любого файла - Secure (оставить, удалить или затереть оригинал, либо случайное имя контейнера), Unsecure (по желанию удалить контейнер или сразу запустить восстановленный файл), Wipe this file, Check this file, Info - и тип документа `.fd-sec` со своим значком: двойной клик - это ровно пункт Unsecure and start: консоль спрашивает пароль, восстанавливает оригинал под его настоящим именем в `%LOCALAPPDATA%\FileDO\reveal` - папку, доступную только этой учётной записи и системе, - передаёт той программе, которой принадлежит его настоящее расширение, и убирает эту копию, когда окно консоли закрывается. В Windows 11 группа находится в «Показать дополнительные параметры»;
- регистрирует **тип контейнера диска .fdd** (компонент *Disk container files (.fdd)*): свой значок, двойной клик, который открывает окно FileDO и подключает виртуальный диск, и пункты *Mount read-only* и *Unmount* в контекстном меню - см. раздел «Виртуальные диски» ниже.

Установщик не подписан цифровой подписью, поэтому при первом запуске Windows может показать «Windows защитила ваш компьютер», а затем запросить права администратора. Сверьте SHA256 (файл `.sha256` опубликован рядом с загрузкой; `certutil -hashfile FileDO-<версия>-setup.exe SHA256`), затем выберите «Подробнее» и «Выполнить в любом случае». Почему предупреждение появляется, зачем нужны права администратора и чего FileDO никогда не делает: [Windows предупредила о FileDO](https://serzhyale.github.io/FileDO/guides/install-trust.html).

Последние три пункта - компоненты, которые можно снять на странице «Choose what to install» установщика и включить или выключить позже через **«Изменить»** в «Приложения и возможности». Для развёртывания без вопросов:

```powershell
# всё сразу, молча
FileDO-<версия>-setup.exe /quiet
# ..с журналом, если потом придётся объяснять результат
FileDO-<версия>-setup.exe /quiet /log install.log
# удалить обратно
FileDO-<версия>-setup.exe /uninstall
```

В том же релизе публикуется и голый `FileDO-<версия>-windows-x64.msi` - ровно этот файл лежит внутри setup EXE - для средств развёртывания, которым нужен пакет и имена компонентов напрямую:

```powershell
msiexec /i FileDO-<версия>-windows-x64.msi /qn ADDLOCAL=Main,ExplorerIntegration,DiskContainerIntegration,DesktopShortcut
msiexec /i FileDO-<версия>-windows-x64.msi /qn ADDLOCAL=Main   # без пунктов Проводника, типа .fdd и значка
```

Удаление программы убирает всё, что записал установщик, включая записи реестра.

#### Вариант 3 - Microsoft Store (MSIX)

Один пакет, два входа: плитка **FileDO** - графический интерфейс со страницей на каждое задание, чья страница «Команда» соберёт и запустит любую команду, и команда `filedo` в `PATH` для любого терминала. В сборке из Store пунктов Проводника **нет**: пакетная сборка получает их только через подписанный обработчик оболочки, а это отдельная работа. Тип файла `.fd-sec` она **назначает**: двойной щелчок по контейнеру открывает окно FileDO на странице «Открыть секретный файл» с уже выбранным контейнером, и пароль спрашивается там. Тип .fdd она тоже назначает, но подключать виртуальные диски сборка из Store не может: двойной щелчок открывает окно FileDO на этом контейнере, где его можно прочитать, проверить и выгрузить - см. раздел «Виртуальные диски» ниже.

#### Вариант 4 - Ручная загрузка

1. **Скачайте** `FileDO-<версия>-windows-x64.zip` из [релизов](https://github.com/SerZhyAle/FileDO/releases/latest) и распакуйте куда угодно.
2. **GUI**: в архиве есть `filedo_win.exe` - запускайте рядом с `filedo.exe` для графического окна (страница на каждое задание и страница «Команда»).
3. **Запуск**: из командной строки или через GUI.

#### Интеграция с Проводником без установщика

winget, переносимый архив и `go install` не запускают установщик и потому не регистрируют ничего. Ту же группу и тот же тип документа можно попросить самому - и забрать обратно так же:

```powershell
filedo fdsec register              # для этого пользователя
filedo fdsec register -all-users   # для всей машины (нужна консоль с правами администратора)
filedo fdsec unregister            # убирает ровно то, что было записано
```

FileDO удаляет только помеченное как своё: тип документа, который тем временем стал принадлежать другой программе, остаётся нетронутым, а тот, кто владел `.fd-sec` до FileDO, получает его обратно. Машину, где уже есть регистрация установщика, команда тоже не трогает - копия для пользователя показывала бы каждый пункт дважды.

## Секретные файлы (`.fd-sec`)

Один файл - или одна папка, всё её дерево - уходит в один контейнер под паролем и возвращается обратно -
из командной строки, из меню Проводника или со страниц группы **Защита** в окне. Настоящее имя оригинала,
его реальный размер и отметки времени запечатаны внутри, а у папки - ещё путь, размер и время каждого
элемента; сам контейнер выдаёт только собственный размер, своё видимое имя и время создания (`rename`
делает безымянный блок данных). По содержимому на диске контейнер папки не отличить от контейнера файла.

```bash
# Упаковать (пароль спрашивается дважды, без эха)
filedo report.docx secure

# Упаковать и избавиться от оригинала - восстановимо и посложнее
filedo report.docx secure del p:hunter2
filedo report.docx secure wipe p:hunter2

# Вернуть под запечатанным именем или в текущую папку
filedo report.fd-sec unsecure
filedo report.fd-sec unsecure here

# Открыть в нужной программе, не распаковывая
filedo report.fd-sec reveal

# Папка упаковывается в один файл так же и возвращается всем деревом
filedo "Налоги 2025" secure
filedo "Налоги 2025.fd-sec" unsecure to D:\Restored

# Тихий набор: ключ потяжелее, никаких следов выравнивания - но открывает только FileDO
filedo report.docx secure suite2
```

Папка упаковывается целиком - вместе с пустыми подпапками - и целиком восстанавливается: сначала во
временную папку, на своё место она переносится только после проверки каждого файла, и никогда не
восстанавливается внутрь или поверх уже существующей папки (с `-y` - под именем с числовым суффиксом).
Папку, в которой есть junction, символическая ссылка или точка монтирования, программа отклоняет, а не
проходит по ссылке. `del` и `wipe` убирают исходное дерево только после чтения контейнера обратно и только
если папка не менялась с момента упаковки. `reveal` открывает один файл, поэтому контейнер папки он
отклоняет и указывает на `unsecure`.

`suite2` запечатывает один файл (не папку) набором 2 вместо набора 1 по умолчанию: ключ Argon2id на 256 МиБ
со свёрткой через перец и XChaCha20-Poly1305 кадрами по 64 КиБ, так что файл - шум с первого байта, без
даже того узора длины по кластерам в 512 байт, который есть у набора 1. Он хранит настоящее имя, реальный
размер и время шифрования, но не собственные отметки времени оригинала - восстановленный файл получает
текущее время. Открывает его только FileDO начиная с этой версии: старые сборки FileDO сообщат о
повреждении или неверном пароле, а приложения FastMediaSorter его не откроют, поэтому по умолчанию остаётся
набор 1. `unsecure`, `reveal`, `fdsec info` и `fdsec verify` определяют набор сами; больше ничего не
меняется, и пустой пароль по-прежнему лишь маскировка.

Пять вещей сказаны прямо, потому что функция безопасности, которая себя переоценивает, хуже, чем никакой:

- **Пустой пароль - это только маскировка, без секретности.** Он принимается, и каждая поверхность,
  которая берёт пароль, говорит, чего он стоит, прямо во время ввода.
- **`wipe` снижает шансы на восстановление и ничего не обещает.** На SSD и на файловых системах с
  копированием при записи или журналированием затирание на месте не гарантирует, что старые блоки исчезли.
- **`wipe` никогда не затирает файл, у которого есть другая жёсткая ссылка.** Затирание на месте достаёт
  до каждого имени файла, поэтому оригинал остаётся, а программа говорит об этом; сначала уберите лишние
  ссылки или используйте `del`.
- **Раскрытая копия живёт в `%LOCALAPPDATA%\FileDO\reveal`**, только для чтения и только для этой учётной
  записи и системы. Она убирается, когда вы скажете, или когда её отпустит открывшая её программа.
- **`unsecure start` - то есть двойной клик - кладёт свою копию в ту же защищённую папку**, а не
  рядом с контейнером, и убирает её при закрытии окна консоли. Эта копия - ваш собственный файл, а
  не версия только для чтения; если программа всё ещё держит её открытой в этот момент, копию
  подметёт следующий запуск FileDO. Насовсем файл возвращает обычный `unsecure`.
- **После сбоя питания эта копия останется на диске до следующего запуска FileDO**, который её подметает.
  Больше её не уберёт ничто.

Ключа восстановления нет: забытый пароль - это потерянный файл. Оригинал остаётся на месте, пока вы не
попросите его убрать, и ничего не удаляется до того, как контейнер записан, перечитан и проверен.
Программы и скрипты никогда не запускаются из контейнера - они извлекаются, и показывается их место.

В окне группа **Защита** несёт те же три операции в виде страниц: пароль скрыт, при упаковке вводится
дважды и передаётся `filedo.exe` незаметно - он не попадает ни в командную строку, ни в отчёт о запуске,
ни в файл истории. Двойной клик по `.fd-sec` этого окна не открывает - он выполняет **Unsecure and start**
в консоли, точно как одноимённый пункт меню Проводника.

## Виртуальные диски (`.fdd`)

Контейнер - это обычный файл `.fdd`, в котором лежит целый том. Подключённый, он становится буквой диска,
как любой другой; отключённый - это файл, который можно копировать, хранить в резервной копии и читать
одним FileDO, не подключая. Формат опубликован полностью - как контракт `FDD-FORMAT`, а то, что обязана
делать читающая или пишущая его программа, - как `FDD-BEHAVIOUR`, - поэтому данные не зависят от того,
останется ли FileDO.

```bash
# Создать контейнер на 20 ГБ (plain: файл растёт по мере записи) и подключить его
filedo vd new work.fdd 20G
filedo work.fdd mount

# Сохранить, пометить закрытым корректно, отключить
filedo X: unmount

# Зашифрованный: vault всегда спрашивает пароль (дважды)
filedo vd new private.fdd 5G vault

# Прочитать без подключения - без прав администратора, в контейнер ничего не пишется
filedo work.fdd info
filedo work.fdd verify
filedo work.fdd export D:\work.vhd vhd

# Изменить, пока он не подключён
filedo work.fdd grow 40G
filedo private.fdd pass
filedo private.fdd clone open-copy.fdd nopass
```

Четыре профиля для `vd new`: `plain` растёт по мере заполнения, `fast` сразу занимает весь размер, `ram`
держит том в памяти, пока он подключён, и сохраняет его в файл каждые несколько секунд (сбой теряет всё,
что записано после последнего сохранения), а `vault` всегда зашифрован. `seal` пишет копию только для
чтения навсегда, `clone` - записываемую копию со своим идентификатором, `compact` возвращает диску
неиспользуемое место файла. `format` стирает том (`fs ntfs` или `fs exfat`), а `destroy` удаляет файл
контейнера (`wipe` сначала его затирает): оба сначала спрашивают и оба отказываются работать с
подключённым контейнером - этот запрет не снимает ни один ключ. `vd add work.fdd as work` даёт контейнеру
короткое имя, `vd list` и `vd status` показывают, что известно и что подключено, а `vd auto work logon`
подключает замаскированный контейнер при входе в Windows. `vd guard on` включает сторож выключения: когда
сеанс заканчивается - выключение, перезагрузка или выход из системы, но не сон, - он сначала сохраняет диски
`ram`, а затем отключает все подключённые контейнеры, чтобы каждый был закрыт чисто; `vd guard status`
показывает его последний запуск. Файлы `.vhd`, `.vhdx` и `.iso` подключаются
средствами самой Windows: `filedo disk.vhdx mount`.

Два слова, два разных обещания, и FileDO никогда их не путает:

- **Без пароля контейнер замаскирован, а не зашифрован.** Маскировка прячет том от случайного взгляда и
  от программ, которые ищут образы дисков, - и ни от кого, у кого есть файл и FileDO. `info` говорит,
  какой из двух случаев перед вами.
- **С паролем он зашифрован**: без пароля файл не прочесть. Восстановления нет - забытый пароль означает
  потерянный контейнер. `pass` меняет пароль, не переписывая данные, поэтому копии файла, сделанные
  раньше, по-прежнему открываются старым паролем.
- **Пароль никогда не снимается на месте.** Пустой новый пароль отклоняется; вместо этого
  `clone <new.fdd> nopass` пишет замаскированную копию, а зашифрованный оригинал остаётся как был.
- **Шифрование защищает файл, а не подключённый том.** Пока том подключён, его читает любая программа,
  которую вы запускаете, как любой другой диск. `export` зашифрованного контейнера тоже не зашифрован, а
  `ram` с паролем позволяет Windows выгрузить незашифрованные данные в файл подкачки.
- **`verify` читает, но не доказывает.** Он читает заголовки, карту и каждый занятый кластер и сообщает о
  повреждениях (код 4), но формат 1.0 не хранит контрольных сумм данных, поэтому данные прочитаны, но не
  сверены.

Что нужно от платформы, прямо:

- **Только Windows.** Букву диска даёт встроенный в Windows инициатор iSCSI, который говорит с блочным
  сервером внутри `filedo.exe`; сервер слушает только адрес 127.0.0.1 - ничего не уходит с этого
  компьютера, и контейнер никогда не попадает ни в какую сеть - если только вы сами не откроете к нему общий доступ (ниже).
- **Подключение требует прав администратора.** `mount`, `unmount`, `save`, `format` и `vd auto` просят у Windows
  согласие администратора на шаг с инициатором; пароль туда не передаётся, а сам блочный сервер никогда
  не работает с повышенными правами. Пакетный файл такого запроса не показывает - запускайте его из
  консоли администратора. Если службой «Инициатор iSCSI (Майкрософт)» воспользоваться нельзя, запуск
  заканчивается кодом 7, и ничего не подключено.
- **Сборка из Microsoft Store не может подключать диски.** Упакованное приложение не может ни настроить
  инициатор iSCSI, ни попросить права администратора, поэтому там `mount`, `unmount`, `save`, `format`,
  `vd auto`, `vd guard` и `vd register` заканчиваются кодом 6. `info`, `verify`, `export`, `compact`, `grow`, `seal`,
  `clone`, `pass`, `destroy`, `vd new`, `vd list`, `vd status`, `vd add` и `vd forget` работают и там; для
  подключения поставьте установщик или переносимую сборку с GitHub.
- **Подключение переживает окно.** Если закрыть окно FileDO, диск и его сервер остаются, а новое окно
  снова показывает их в списке; отключайте в Диспетчере дисков, на страницах группы «Диски» или командой `filedo X: unmount`.

В **Диспетчере дисков** выберите зарегистрированный файловый диск и **«Поделиться через Fast Media Sorter & Sharing..»** в панели сведений или меню «Ещё» (`Ctrl+Shift+S`). Сначала запустите Share Manager этой программы. Если worker недоступен, диалог предлагает повторную проверку и [страницу установки](https://serzhyale.github.io/FastMediaSorter_Lite/); недоступность worker не означает отсутствия программы. При необходимости включите дополнительный компонент дисков FileDO. Настольный установщик не подписан. По умолчанию доступ на чтение и запись, «только на чтение» включается галочкой; sealed-диск всегда доступен только на чтение. Укажите имя папки и при желании откройте её сопряжённым устройствам. Уже подключённый в FileDO диск отключается безопасно после подтверждения; RAM сохраняется штатным отключением. Если включено автоподключение FileDO, явно согласитесь выключить его; ручной режим `keep` завершается при отключении. Автозапуск FMS включается отдельно. **«Закрыть общий диск»** сохраняет регистрацию; **«Прекратить шаринг»** удаляет её и сохранённый ключ автозапуска FMS. При ошибке выполненные шаги сохраняются: обновите список, повторите оставшееся действие или прекратите шаринг перед явным восстановлением локального подключения и прежней автоматической политики. Сопрягайте устройства через Share Manager. Файлы передаются по SFTP, SMB-шара Windows не создаётся. Сеансовый режим требует входа в систему; служба доступна без входа. Диски в разделах и управление внешним worker из непроверенной Store-сборки здесь недоступны; используйте настольную сборку. Пошаговая страница - что нужно, каждый диалог и восстановление - здесь: [Общий доступ к дискам FileDO через Fast Media Sorter](https://serzhyale.github.io/FileDO/guides/fms-sharing.html).

**Общий доступ к диску через Fast Media Sorter for Windows (по желанию).** Если установлена Fast Media Sorter
for Windows, `vd share work.fdd on` предлагает диск телефонам и планшетам, которые вы с ней связали, как ещё
одну папку; `vd open`, `vd close` и `vd autostart` открывают его для них, закрывают и открывают снова после
перезапуска. FileDO не открывает для этого сетевых соединений - он говорит с той программой по локальному
каналу, а файлы отдаёт она. Зашифрованный диск разблокируется здесь, на этом компьютере, и никогда с телефона;
пока он открыт, его файлы может читать каждое связанное устройство, а `vd autostart` хранит его пароль на этом
компьютере, защищённым для той программы, пока вы не выключите автозапуск, не прекратите доступ или не смените
пароль. Общий диск держит та программа, поэтому `mount` отказывает, пока она его держит; `vd status` говорит,
кто держит. Только серверная редакция Fast Media Sorter for Windows держит общие диски доступными, когда никто
не вошёл в систему.

Коды выхода одной команды над контейнером: 0 готово, 2 ошибка в команде, 3 неверный пароль,
4 повреждение, 5 ошибка ввода-вывода, 6 не поддерживается, 7 транспорт недоступен, 8 занят (подключён,
открыт или заблокирован). Пакетный файл сохраняет 0/1/2.

В Проводнике компонент установщика *Disk container files (.fdd)* (`DiskContainerIntegration`) даёт `.fdd`
свой значок и три пункта, которые открывают окно FileDO. Двойной клик подключает: чистый замаскированный
контейнер - сразу; зашифрованный спрашивает пароль в окне, никогда не в командной строке; контейнер,
который не был закрыт корректно, сначала говорит об этом со временем последнего полного сохранения и ждёт;
уже подключённый открывает свой диск. Контекстное меню добавляет *Mount read-only* и *Unmount* (в Windows 11 они
в «Показать дополнительные параметры»). Без установщика то же самое записывает `filedo vd register`
(добавьте `-all-users` для всей машины), а `filedo vd unregister` убирает. В окне группа **«Диски»** несёт
по странице на каждую операцию и называет обе защиты точно так же, как консоль.

**Диспетчер дисков** - второе окно той же `filedo_win.exe`, а не новая программа, - по строке на виртуальный диск: диски из вашего списка, диски, подключённые сейчас, и образы VHD, VHDX или ISO, которые подключил FileDO. Строка показывает состояние словами рядом со значком («Подключён», «Подключён, только чтение», «Подключён, не сохранено 180 MiB» для диска `ram`, «Сервер пропал - том недоступен», «Образ подключён», «Файл пропал», «По этому пути другой контейнер», «Не читается», «Закрыт некорректно», «Не подключён»), а список сам поддерживает актуальность без ручного обновления. Вокруг него - панель кнопок («Новый диск..», «Добавить..», «Подключить», «Отключить», «Открыть», «Сохранить», «Ещё», «Обновить», «Справка», «Главное окно»), строка фильтра и панель подробностей с подходящими кнопками; недоступная кнопка говорит, почему, в подсказке и в панели, а сборка из Microsoft Store, которая подключать не может вовсе, прячет элементы подключения, а не делает их серыми. Двойной клик или Enter подключает неподключённый диск и открывает том подключённого - никогда не отключает; перетащите файлы `.fdd` на список, чтобы добавить их, а `.vhd`, `.vhdx` или `.iso` - чтобы подключить образ после одного подтверждения. «Новый диск..» сначала спрашивает, где диск будет хранить данные: «Файл на диске..» открывает страницу «Создать диск» в главном окне, «Раздел в свободном месте..» - собственный диалог диспетчера для раздела: карта свободного места каждого GPT-диска, размер, профиль, метка и имя (сборка из Microsoft Store предлагает только файл). Для диска-файла «Экспорт», «Сжать», «Увеличить», «Запечатанная копия», «Клонировать», «Сменить пароль», «Форматировать» и «Уничтожить» открывают свою страницу задания в главном окне с уже выбранным контейнером; «Форматировать» и «Уничтожить» сохраняют там подтверждение, которое нужно набрать. Строка [диска-раздела](#диски-разделы) говорит «Раздел не подключён» или «Раздел изменился», если он не там, где был зарегистрирован, предлагает «Образ в файл..», чтобы скопировать его в новый файл `.fdd`, а удаляется он в самом диспетчере: «Уничтожить» просит набрать его имя и может сначала перезаписать раздел. «Принять раздел..» (в «Ещё» или правым щелчком по пустому месту) показывает разделы FileDO на дисках этого компьютера, которых нет в списке, и добавляет выбранный под заданным именем; сборка из Microsoft Store прячет «Образ в файл» и «Принять раздел».

Открывается он пунктом **FileDO Disk Manager** в меню «Пуск» (его добавляет установщик; пункт запускает `filedo_win.exe --disks`), кнопкой **«Диспетчер дисков»** справа вверху окна FileDO или первой строкой его группы «Диски» (также **Ctrl+Shift+D**), либо командой `filedo_win.exe --disks`; его кнопка **«Главное окно»** выводит окно FileDO вперёд. **F1** открывает справку - что говорит строка, таблица клавиш, ссылки. При первом открытии диспетчера окно приветствия объясняет, что такое виртуальный диск, и говорит: *Замаскирован, а не зашифрован: его прочтёт любой, у кого есть этот файл и FileDO. Открывается без пароля.* *Зашифрован: открывается только своим паролем.* Там же сказано, что согласие администратора Windows спрашивает при каждом подключении и отключении, а для диска-раздела - ещё и при каждом чтении, и предложено «Создать мой первый диск..», «Добавить файл .fdd, который у меня уже есть..», «Прочитать руководство на сайте» и «Не сейчас». Таблица клавиш и снимки - в [руководстве по виртуальным дискам](https://serzhyale.github.io/FileDO/guides/virtual-disks.html#manager). Закрытие диспетчера никогда не отключает диск.

### Диски-разделы

Виртуальный диск может жить не только в файле, но и в разделе. FileDO создаёт новый раздел GPT в
нераспределённом пространстве диска и целиком заполняет его одним контейнером; за пределами этого
свободного места ничего не меняется - FileDO никогда не преобразует существующий раздел, не меняет его
размер и не пишет в него. Только диски GPT: диски MBR, динамические диски, дисковые пространства (Storage
Spaces), диски iSCSI, съёмные и USB-диски отклоняются, и `vd disks` называет причину для каждого. Вы
получаете диск, который не держит никакая файловая система-хозяин, которому Windows не даёт букву и не
предлагает отформатировать, с заранее закреплённым местом; чего вы не получаете - так это скорости.

```bash
# Все диски, их разделы и свободное место - каждый участок пригоден или нет и почему (без прав администратора)
filedo vd disks

# Диск-раздел на весь свободный участок (строку create печатает vd disks) с именем data
filedo vd new part disk:{GPT-GUID} size max at <offset> as data
filedo vd mount data

# Скопировать его в обычный файл .fdd, который читается без прав администратора
filedo vd image data to D:\data.fdd

# Зарегистрировать раздел FileDO, которого этот компьютер не знает (диск перенесли с другого компьютера)
filedo vd adopt fdpart:{GUID} as data

# Удалить раздел: для подтверждения наберите имя диска; место снова становится нераспределённым
filedo vd destroy data
```

`<disk>` - это `disk:{GUID}` или номер, который напечатал `vd disks`; `size` - `max` или размер вроде `40G`
(округляется вниз до 1 MiB, не меньше 64 MiB). Профиль по умолчанию - `fast`; `plain`, `vault` и `ram` тоже
работают. Первое подключение форматирует том в NTFS. К диску-разделу обращаются по имени или по локатору
`fdpart:{GUID}`, пути у него нет; `mount`, `unmount`, `save`, `info`, `verify`, `export`, `pass`, `seal`,
`clone`, `vd auto` и сторож выключения работают так же, как с файлом, `compact` и `grow` - нет (размер
раздела постоянен), а общий доступ через Fast Media Sorter пока отклоняется. `vd forget` убирает имя и
оставляет раздел на диске; `vd destroy .. wipe` перед удалением затирает раздел. Отклонённый диск
заканчивается кодом 6, отказ в согласии - кодом 7, а разметка, изменившаяся с тех пор, как её показал
список, - кодом 5, и при этом ничего не изменено.

- **Согласие администратора нужно для каждого чтения, а не только для подключения.** Раздел нельзя открыть
  без прав администратора, поэтому `info`, `verify`, `export`, `pass`, `seal`, `clone` и `vd image` тоже
  просят у Windows согласие. `vd image` снимает эту необходимость: файл, который он пишет, - обычный `.fdd`,
  и любой путь чтения открывает его без прав администратора.
- **Не быстрее файлового диска.** В замере от начала до конца на накопителе NVMe диск-раздел оказался
  медленнее файла `.fdd` на NTFS. Выбирайте его ради отдельного закреплённого места, а не ради скорости.
- **`fast` перезаписывает свободное место, `plain` и `vault` - нет.** Всё, что раньше лежало в свободном
  месте, остаётся в неиспользуемых кластерах диска-раздела `plain` или `vault`, пока том не запишет поверх;
  `fast` перезаписывает весь раздел при создании.
- **«Управление дисками» Windows (`diskmgmt.msc`) по-прежнему показывает раздел и может его удалить.**
  Удаление там удаляет и диск внутри, ни о чём не спрашивая про его содержимое. Безопасный путь - собственный
  `vd destroy` FileDO: он отказывается работать с подключённым диском, просит набрать имя диска и удаляет
  только раздел, про который доказал, что это раздел FileDO.
- **Диски-разделы недоступны в версии из Microsoft Store.** Там `vd disks` говорит об этом, а каждая
  команда для разделов заканчивается кодом 6; используйте установщик или переносимую сборку с GitHub.

## Ключевые возможности

### **Обнаружение поддельной ёмкости**
- **100-файловая проверка** с 1% ёмкости каждый
- **Случайная позиционная проверка** - каждый файл проверяется в уникальных случайных позициях
- **Защита от сложных подделок** - побеждает контроллеры, сохраняющие предсказуемые позиции данных
- **Читаемые паттерны** - использует `ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789` для лёгкого обнаружения повреждений
- **Быстрое зондирование** (`probe`) - 32 маркера через прямой доступ к LBA, завершается за ~1 мин (нужны права администратора)

### **Тестирование производительности**
- Измерение реальной скорости чтения/записи
- Оптимизированная потоковая передача для больших файлов
- Отслеживание прогресса с расчётом ETA
- Настраиваемые размеры файлов (1МБ до 10ГБ)

### **Управление дубликатами файлов**
- **Встроенное обнаружение дубликатов** - интегрировано в основное приложение
- **Несколько режимов выбора** (старейший/новейший по времени создания, алфавитный)
- **Гибкие действия** (удалить/переместить дубликаты) - о каждом файле спрашивается, если не указан `-y` (или `--yes`); запуск без консоли и без `-y` отклоняется до того, как что-либо тронуто
- **Группировка по SHA-256 и побайтовое сравнение с оставляемой копией** непосредственно перед каждым удалением или перемещением; хеш, из кэша или свежий, никогда не единственное доказательство, а перемещение никогда не заменяет существующий файл, в том числе на другой диск
- **Жёсткие ссылки и второе имя того же файла** не считаются дубликатами; корень диска или общей папки, Windows, Program Files и системный TEMP требуют набранного подтверждения даже с `-y`, а сканирование пропускает Windows и Program Files, если не начато внутри них
- **Кэширование хешей** для более быстрых повторных сканирований - кэш (`hash_cache.json`) хранится в `%LOCALAPPDATA%\FileDO\state\`, и хеш из него используется, только пока размер, время изменения, идентификатор файла и время последней смены (change time) совпадают
- **Сохранение/загрузка списков дубликатов** для пакетной обработки
- **Модульная архитектура** с выделенным пакетом fileduplicates

### **Операции копирования**
- **Отслеживание прогресса** с детальными расчётами ETA
- **Защита таймаутом** для повреждённых/медленных файловых систем (3-секундный таймаут)
- **Сохранение метаданных** - права доступа и времена изменения файлов
- **Надёжная обработка ошибок** - продолжает копирование даже при сбоях отдельных файлов
- **Универсальная поддержка** - работает с устройствами, папками, сетевыми ресурсами и отдельными файлами

### **Операции очистки**
- **Только содержимое** - удаляется всё внутри папки, а сама папка остаётся - со своими правами доступа, владельцем, шифрованием, сжатием и атрибутами
- **Честный итог** - то, что удалить не удалось (занято, заблокировано, нет доступа), выводится списком, код выхода 2
- **Универсальная совместимость** - поддерживает устройства (`device D: wipe` всегда означает `D:\`), папки и сетевые ресурсы
- **Защита от ошибок** - корни дисков и ресурсов в любом написании, а также папки TEMP, профиля, Windows, Program Files и FileDO вместе со всеми папками над ними всегда требуют ввода подтверждения, и `--force` его не отменяет; соединение (junction) или символическая ссылка отклоняются сразу

### **Функции безопасности**
- **Высокоскоростное безопасное удаление данных** для предотвращения восстановления
- **Операции заполнения** с оптимизированным управлением буферами
- **Пакетная обработка** для нескольких целей
- **Комплексная история операций** с JSON логированием
- **Контекстное прерывание** - поддержка изящной отмены

## Справочник команд

### Типы целей (Автоматическое определение)
| Шаблон | Тип | Пример |
|---------|------|---------|
| `C:`, `D:` | Устройство | `filedo C: test` |
| `C:\folder` | Папка | `filedo C:\temp speed 100` |
| `\\server\share` | Сеть | `filedo \\nas\backup test` |
| `file.txt` | Файл | `filedo document.pdf info` |

### Операции
| Команда | Назначение | Пример |
|---------|---------|---------|
| `info` | Показать подробную информацию | `filedo C: info` |
| `short` | Краткая сводка | `filedo D: short` |
| `test` | Обнаружение поддельной ёмкости | `filedo E: test del` |
| `test N` | Тест с N файлами (по умолчанию 100) | `filedo D: test 1000` |
| `probe` | Быстрое зондирование через сырой I/O (~1 мин, нужны права админа) | `filedo D: probe` |
| `speed <size>` | Тестирование производительности | `filedo C: speed 500` |
| `fill [size]` | Заполнить тестовыми данными | `filedo D: fill 1000` |
| `clean` | Удалить тестовые файлы | `filedo C: clean` |
| `check-duplicates` | Найти дубликаты файлов | `filedo C: check-duplicates` |
| `cd [mode] [action]` | Проверить дубликаты (короткая форма) | `filedo D:\Photos cd old del -y` |
| `copy <target>` | Копировать файлы с прогрессом | `filedo C: copy D:\backup` |
| `wipe` | Удаление всего содержимого папки | `filedo folder C:\temp wipe` |
| `from <file>` | Выполнить пакетные команды | `filedo from script.txt` |
| `hist` | Показать историю операций | `filedo hist` |

### Модификаторы
| Флаг | Назначение | Пример |
|------|---------|---------|
| `del` | Автоудаление после операции | `filedo E: test del` |
| `nodel` | Сохранить тестовые файлы | `filedo C: speed 100 nodel` |
| `short` | Только краткий вывод | `filedo D: speed 100 short` |
| `max` | Максимальный размер (10ГБ) | `filedo C: speed max` |
| `old` | Оставить новейший как оригинал (для cd) | `filedo D:\Photos cd old del` |
| `new` | Оставить старейший как оригинал (для cd) | `filedo E:\Photos cd new move F:\Dups` |
| `abc` | Оставить алфавитно последний (для cd) | `filedo C: cd abc` |
| `xyz` | Оставить алфавитно первый (для cd) | `filedo C: cd xyz list dups.lst` |
| `-y`, `--yes` | Удалять/перемещать дубликаты без вопроса о каждом файле (для cd; обязателен без консоли) | `filedo D:\Photos cd old del -y` |

## GUI Приложение

**FileDO GUI** (`filedo_win.exe`) - оболочка на VB.NET (Windows Forms): слева перечень заданий, на каждое задание своя нумерованная страница - что обрабатывать, какие параметры, затем проверка и запуск - плюс страница **«Команда»**, экспертный конструктор, который соберёт и запустит **любую** команду FileDO. Что есть в окне:

- **5 языков интерфейса** (EN / RU / UA / DE / FR, запоминается) и **панель помощи**: что делает операция и флаги, какой будет итог, и пример для цели
- **Выбор цели** (устройство / папка / сеть / файл); для **устройства** путь становится **выбором буквы диска**, а выбор системного диска поясняет перенаправление в `%TEMP%\FileDO_Operations`
- **Все операции** на странице «Команда», в одном списке: info, speed, test, fill, clean, cd (дубликаты), всё семейство copy (copy / fastcopy / synccopy / balanced / maxcopy / smartcopy / safecopy), wipe, compare, check, probe, recover, from, hist
- **Источник и назначение** для copy и compare
- **Флаги по контексту** (max, del, nodel, short, hist, `--force` для wipe) и правила удаления для дубликатов/сравнения
- **Страница на задание** в окне по умолчанию - ёмкость, скорость, сведения, проверка повреждённых файлов, прямая проверка, восстановление, дубликаты, сравнение, очистка, копирование, заполнение, стирание и три задания для секретных файлов - и на каждой все опции, какие принимает CLI, включая все двадцать девять флагов `check`
- **Живой предпросмотр** в редактируемом поле на странице «Команда» - правьте вручную всё, что не покрыл конструктор
- Кнопки **Browse** для путей, **Copy command** в буфер и **RUN** в окне консоли
- Находит `filedo.exe` рядом с собой или в `PATH` (работает и в пакете Store, и в портативном zip)
- **Страница «О программе»**: сборка, автор и ссылки на сайт, исходный код, трекер проблем, страницу приватности и другие программы автора
- **Отправить логи автору** - единственная кнопка на этой странице собирает найденные на машине логи FileDO в один zip, открывает папку с выделенным файлом, копирует путь в буфер обмена и открывает вашу почтовую программу с уже заполненным адресом и темой. Zip вы сначала видите сами, и ничего не уходит, пока вы сами не отправите письмо

```powershell
filedo_win              # если в PATH (winget / Store)
filedo_win.exe          # рядом с filedo.exe в портативном zip
```

Страницы **«Защита»** работают с секретными файлами `.fd-sec` - сделать файл секретным, вернуть оригинал или открыть его без распаковки. Пароль скрыт маской и никогда не попадает в командную строку. Если передать окну путь к `.fd-sec` напрямую, оно откроется на странице этого контейнера (`filedo_win.exe C:\a\x.fd-sec`); двойной щелчок в Проводнике окно вообще не задействует - он выполняет **Unsecure and start** в консоли, как описано выше. «История», «Настройки» и «О программе» имеют собственные страницы; прежнее окно-конструктор команд выведено из употребления, а командную строку вручную пишут на странице **«Команда»**. **Диспетчер дисков** - второе окно для виртуальных дисков, которое открывают клавишами **Ctrl+Shift+D**, кнопкой справа вверху или командой `filedo_win.exe --disks`, - описан в разделе *Виртуальные диски* выше.

**Едет везде:** GUI входит в пакет winget, портативный zip, MSI и является плиткой пакета Microsoft Store (MSIX).

## Важные замечания

> **Обнаружение поддельной ёмкости**: Создаёт 100 файлов (по 1% ёмкости каждый) с **поддержкой контекстного прерывания**. Использует современные случайные паттерны проверки и оптимизированное управление буферами для надёжного обнаружения.

> **Улучшенное прерывание**: Все долгие операции поддерживают **изящную отмену Ctrl+C** с автоматической очисткой. Контекстные проверки прерывания в оптимальных точках для немедленной отзывчивости.

> **Безопасное удаление**: `fill <size> del` перезаписывает свободное место с оптимизированным управлением буферами и контекстной записью для безопасного удаления данных.

> **Тестовые файлы**: Создаёт файлы `FILL_*.tmp` и `speedtest_*.txt`. `clean` удаляет только те, что записал FileDO, - с его именами и его содержимым, больше ничего, - сначала показав список и спросив; `--yes` отвечает на вопрос.

> **Общие пакеты**: `fileduplicates` (поиск дубликатов), `fsx` (идентичность путей и атомарная запись без замены) и `statedir` (корень состояния, `%LOCALAPPDATA%\FileDO\state`).

## Технические детали

### Архитектура
- **Модульный дизайн**: Разделен на специализированные пакеты для лучшей поддерживаемости
- **Контекстные операции**: Все долгие операции поддерживают изящную отмену
- **Единый интерфейс**: Общий интерфейс `Tester` для всех типов накопителей
- **Оптимизация памяти**: Потоковые операции с оптимизированным управлением буферами
- **Кроссплатформенность**: Основная поддержка Windows с портируемой кодовой базой Go

### Структура пакетов
```
FileDO/
├── main.go                    # Точка входа приложения
├── fsx/                      # Идентичность путей и атомарная запись
├── statedir/                 # Где лежат файлы состояния (%LOCALAPPDATA%\FileDO\state)
├── fileduplicates/           # Управление дубликатами файлов
│   ├── types.go              # Интерфейсы обнаружения дубликатов
│   ├── duplicates.go         # Основная логика дубликатов
│   ├── duplicates_impl.go    # Детали реализации
│   └── worker.go             # Фоновая обработка
├── filedo_win_vb/           # GUI приложение VB.NET
│   ├── FileDOGUI.sln        # Решение Visual Studio
│   ├── Program.vb           # Точка входа; окно - ShellForm.vb
│   └── bin/                 # Скомпилированный GUI исполняемый файл
├── command_handlers.go       # Обработка команд
├── device_windows.go         # Операции с устройствами
├── folder.go                 # Операции с папками
├── network_windows.go        # Операции с сетевыми накопителями
├── interrupt.go              # Обработка прерываний
├── progress.go               # Отслеживание прогресса
├── main_types.go             # Устаревшие определения типов
├── history.json              # История операций
└── hash_cache.json           # Кэш хешей для дубликатов
```

### Ключевые возможности
- **Улучшенный InterruptHandler**: Потокобезопасное прерывание с поддержкой контекста
- **Оптимизированное управление буферами**: Динамическое изменение размера буферов для оптимальной производительности
- **Комплексное тестирование**: Обнаружение поддельной ёмкости со случайной проверкой
- **Обнаружение дубликатов**: Сравнение файлов по SHA-256 с кэшированием и побайтовая проверка перед любым удалением или перемещением
- **Пакетная обработка**: Выполнение скриптов с обработкой ошибок
- **Ведение истории**: Отслеживание операций на основе JSON

- **Проводник**: новый компонент установщика *Disk container files (.fdd)* (`DiskContainerIntegration`) даёт `.fdd` значок, подключение двойным кликом и пункты *Mount read-only* / *Unmount*; без установщика то же делает `filedo vd register`
- **GUI**: новая группа **«Диски»** - по странице на операцию - и **Диспетчер дисков**, второе окно со строкой на каждый виртуальный диск, состоянием словами и подключением, отключением, открытием и сохранением прямо из строки; подключённый диск переживает закрытие окна, а установщик добавляет пункт *FileDO Disk Manager* в меню «Пуск», который открывает его сразу
- **Ограничения**: только Windows; подключение просит согласие администратора; сборка из Microsoft Store читает, проверяет и выгружает контейнеры, но подключать их не может
