## Быстрый старт

### Наиболее частые задачи

```bash
# Проверить поддельность USB/SD карты
filedo E: test del

# Тест производительности диска
filedo C: speed 100

# Безопасная очистка свободного места
filedo D: fill 1000 del

# Поиск и управление дубликатами файлов
filedo C: check-duplicates
filedo D:\Photos cd old del

# Копирование с прогрессом
filedo folder C:\Source copy D:\Backup
filedo device E: copy F:\Archive
# Сначала сосчитать дерево ради точного оставшегося времени (иначе копирование начинается с первого файла)
filedo folder C:\Source copy D:\Backup --precount

# Быстрая очистка папок
filedo folder C:\Temp wipe
filedo folder D:\Cache w

# Показать информацию о диске
filedo C: info
```

### Сравнение папок и очистка

```bash
# Сравнить две папки и сохранить отчёт
filedo compare D:\Data E:\Backup

# Сравнить и удалить (перманентно, без подтверждения)
filedo cmp D:\Data E:\Backup del source  # удалить в Source, если есть в Target
filedo cmp D:\Data E:\Backup del target  # удалить в Target, если есть в Source
filedo cmp D:\Data E:\Backup del old     # удалить более старый (mtime), равные: пропуск
filedo cmp D:\Data E:\Backup del new     # удалить более новый (mtime), равные: пропуск
filedo cmp D:\Data E:\Backup del small   # удалить меньший, равные: пропуск
filedo cmp D:\Data E:\Backup del big     # удалить больший, равные: пропуск
 
# Необязательная сторона (ограничение по стороне)
filedo cmp D:\Data E:\Backup del small source  # только если меньший на Source
filedo cmp D:\Data E:\Backup del big target    # только если больший на Target
filedo cmp D:\Data E:\Backup del old target    # только если старший на Target
filedo cmp D:\Data E:\Backup del new source    # только если новейший на Source
```

Примечания: сопоставление по относительному пути; `del source` и `del target` удаляют пару, только если совпадают размер и время изменения (`--by-hash` - совпадает содержимое; `--allow-mismatch` - любую пару), а несовпавшая пара выводится и остаётся; два написания одной папки или папка внутри другой отклоняются; mtime для old/new; Windows - без учёта регистра, а удаление идёт по настоящему имени файла; если что-то не удалось прочитать или удалить, код выхода 2; логи: compare_report_*.log, delete_report_<mode>_*.log.

### CHECK - быстрая проверка чтения

```bash
# Проверка папки: читаем файлы; если задержка первого чтения > 2.0с - файл помечается как повреждённый
filedo check F:\Mov
```

- Однократный «прогрев» до 10.0с перед первым чтением (пробуждение HDD)
- Списки повреждённых и «хороших» файлов лежат в `%LOCALAPPDATA%\FileDO\state` (никогда не рядом с вашими файлами) и называют файл путём, размером и временем изменения - изменённый файл читается снова; у copy свой, отдельный список пропуска
- Файл из списка повреждённых снова считается повреждённым без повторного чтения (код 1); заблокированный или нечитаемый файл или папка - «не удалось проверить» (код 2), а не «повреждён»
- Параллельные воркеры; поддержка Ctrl+C

#### Флаги CHECK (флаги имеют приоритет над переменными окружения)

Флаги дублируют FILEDO_CHECK_* и удобны для интерактивного запуска.

- Общие
	- `--threshold <sec>` (FILEDO_CHECK_THRESHOLD_SECONDS)
	- `--warmup <sec>` (FILEDO_CHECK_WARMUP_SECONDS)
	- `--warmup-idle <sec>` (FILEDO_CHECK_WARMUP_IDLE_RESET_SECONDS)
	- `--workers <int>` (FILEDO_CHECK_WORKERS)
	- `--buf-kb <int>` (FILEDO_CHECK_BUF_KB)
	- `--mode quick|balanced|deep` (FILEDO_CHECK_MODE)
	- `--balanced-min-mb <int>` (FILEDO_CHECK_BALANCED_MIN_MB)
	- `--min-mb <float>` / `--max-mb <float>` (FILEDO_CHECK_MIN_MB / FILEDO_CHECK_MAX_MB)
	- `--include-ext ".jpg,.png"` / `--exclude-ext ".bak,.tmp"` (FILEDO_CHECK_INCLUDE_EXT / FILEDO_CHECK_EXCLUDE_EXT)
- Ограничения
	- `--max-files <int>` (FILEDO_CHECK_MAX_FILES)
	- `--max-seconds <float>` (FILEDO_CHECK_MAX_DURATION_SEC)
	- `--precount` / `--no-precount` (FILEDO_CHECK_PRECOUNT)
- Поведение и вывод
	- `--dry-run` (FILEDO_CHECK_DRYRUN)
	- `--verbose` (FILEDO_CHECK_VERBOSE)
	- `--quiet` (FILEDO_CHECK_QUIET)
	- `--resume` (FILEDO_CHECK_RESUME) - продолжить: пропустить файлы, которые прошлый запуск уже прочитал без ошибок («хороший» список)
- Отчёты
	- `--report csv|json` (FILEDO_CHECK_REPORT)
	- `--report-file <path>` (FILEDO_CHECK_REPORT_FILE)
- Кэш «хороших» файлов
	- `--good-list <path>` (FILEDO_CHECK_GOODLIST)
- Режим single-reader и адаптивная пауза (для HDD/USB)
	- `--single-reader auto|on|off` (FILEDO_CHECK_SINGLE_READER)
	- `--ewma-alpha <float>` (FILEDO_CHECK_EWMA_ALPHA)
	- `--ewma-high-frac <float>` (FILEDO_CHECK_EWMA_HIGH_FRAC)
	- `--ewma-low-frac <float>` (FILEDO_CHECK_EWMA_LOW_FRAC)
	- `--max-sleep-ms <int>` (FILEDO_CHECK_MAX_SLEEP_MS)
	- `--sleep-step-ms <int>` (FILEDO_CHECK_SLEEP_STEP_MS)
	- `--hdd-sleep-ms <int>` (FILEDO_CHECK_HDD_SLEEP_MS) - постоянная пауза после каждого файла, у каждого читателя

Примеры:

```bash
# Balanced-режим, фикс кол-ва потоков, подсчёт для стабильной ETA
filedo check D:\Data --mode balanced --workers 6 --threshold 1.8 --precount

# Принудительно один читатель + адаптивная пауза по EWMA
filedo check F:\Photos --single-reader on --ewma-alpha 0.2 --max-sleep-ms 250

# Фильтрация по расширениям, лимит по кол-ву и CSV-отчёт
filedo check D:\Media --include-ext .jpg,.png --max-files 1000 --report csv --report-file D:\rep.csv

# Свой список «хороших» файлов и тихий вывод
filedo check D:\Data --good-list D:\check_files.list --quiet
```

### Установка

#### Вариант 1 - winget (рекомендуется)

```powershell
winget install SerZhyAle.FileDO
```

Ставит инструменты командной строки (`filedo`, `filedo_check`, `filedo_fill`, `filedo_test`) и графическое окно `filedo_win` (страница на каждое задание), и добавляет их в `PATH`.

Также есть в [Microsoft Store](https://apps.microsoft.com/detail/9PH1LPCMRG83) - те же инструменты, установку и обновления берёт на себя Store.

#### Вариант 2 - Установщик (setup EXE)

Скачайте `FileDO-<версия>-setup.exe` из [релизов](https://github.com/SerZhyAle/FileDO/releases/latest) и запустите. Именно этот вариант делает FileDO обычной программой Windows, а не папкой с исполняемыми файлами:

- ставит файлы в `C:\Program Files\FileDO` и добавляет `filedo` в системный `PATH`;
- создаёт **пункт в меню «Пуск»** и **значок на рабочем столе** для окна FileDO (`filedo_win.exe`);
- регистрирует **интеграцию с Проводником**: группу `File DO..` в контекстном меню любого файла - Secure (оставить, удалить или затереть оригинал, либо случайное имя контейнера), Unsecure (по желанию удалить контейнер или сразу запустить восстановленный файл), Wipe this file, Check this file, Info - и тип документа `.fd-sec` со своим значком: двойной клик - это ровно пункт Unsecure and start: консоль спрашивает пароль, восстанавливает оригинал под его настоящим именем в `%LOCALAPPDATA%\FileDO\reveal` - папку, доступную только этой учётной записи и системе, - передаёт той программе, которой принадлежит его настоящее расширение, и убирает эту копию, когда окно консоли закрывается. В Windows 11 группа находится в «Показать дополнительные параметры».

Установщик не подписан цифровой подписью, поэтому при первом запуске Windows может показать «Windows защитила ваш компьютер», а затем запросить права администратора. Сверьте SHA256 (файл `.sha256` опубликован рядом с загрузкой; `certutil -hashfile FileDO-<версия>-setup.exe SHA256`), затем выберите «Подробнее» и «Выполнить в любом случае». Почему предупреждение появляется, зачем нужны права администратора и чего FileDO никогда не делает: [Windows предупредила о FileDO](https://serzhyale.github.io/FileDO/guides/install-trust.html).

Последние два пункта - компоненты, которые можно снять на странице «Choose what to install» установщика и включить или выключить позже через **«Изменить»** в «Приложения и возможности». Для развёртывания без вопросов:

```powershell
# всё сразу, молча
FileDO-<версия>-setup.exe /quiet
# ..с журналом, если потом придётся объяснять результат
FileDO-<версия>-setup.exe /quiet /log install.log
# удалить обратно
FileDO-<версия>-setup.exe /uninstall
```

В том же релизе публикуется и голый `FileDO-<версия>-windows-x64.msi` - ровно этот файл лежит внутри setup EXE - для средств развёртывания, которым нужен пакет и имена компонентов напрямую:

```powershell
msiexec /i FileDO-<версия>-windows-x64.msi /qn ADDLOCAL=Main,ExplorerIntegration,DesktopShortcut
msiexec /i FileDO-<версия>-windows-x64.msi /qn ADDLOCAL=Main   # без пунктов Проводника и значка
```

Удаление программы убирает всё, что записал установщик, включая записи реестра.

#### Вариант 3 - Microsoft Store (MSIX)

Один пакет, два входа: плитка **FileDO** - графический интерфейс со страницей на каждое задание, чья страница «Команда» соберёт и запустит любую команду, и команда `filedo` в `PATH` для любого терминала. В сборке из Store пунктов Проводника **нет**: пакетная сборка получает их только через подписанный обработчик оболочки, а это отдельная работа. Тип файла `.fd-sec` она **назначает**: двойной щелчок по контейнеру открывает окно FileDO на странице «Открыть секретный файл» с уже выбранным контейнером, и пароль спрашивается там.

#### Вариант 4 - Ручная загрузка

1. **Скачайте** `FileDO-<версия>-windows-x64.zip` из [релизов](https://github.com/SerZhyAle/FileDO/releases/latest) и распакуйте куда угодно.
2. **GUI**: в архиве есть `filedo_win.exe` - запускайте рядом с `filedo.exe` для графического окна (страница на каждое задание и страница «Команда»).
3. **Запуск**: из командной строки или через GUI.

#### Интеграция с Проводником без установщика

winget, переносимый архив и `go install` не запускают установщик и потому не регистрируют ничего. Ту же группу и тот же тип документа можно попросить самому - и забрать обратно так же:

```powershell
filedo fdsec register              # для этого пользователя
filedo fdsec register -all-users   # для всей машины (нужна консоль с правами администратора)
filedo fdsec unregister            # убирает ровно то, что было записано
```

FileDO удаляет только помеченное как своё: тип документа, который тем временем стал принадлежать другой программе, остаётся нетронутым, а тот, кто владел `.fd-sec` до FileDO, получает его обратно. Машину, где уже есть регистрация установщика, команда тоже не трогает - копия для пользователя показывала бы каждый пункт дважды.

## Секретные файлы (`.fd-sec`)

Один файл - или одна папка, всё её дерево - уходит в один контейнер под паролем и возвращается обратно -
из командной строки, из меню Проводника или со страниц группы **Защита** в окне. Настоящее имя оригинала,
его реальный размер и отметки времени запечатаны внутри, а у папки - ещё путь, размер и время каждого
элемента; сам контейнер выдаёт только собственный размер, своё видимое имя и время создания (`rename`
делает безымянный блок данных). По содержимому на диске контейнер папки не отличить от контейнера файла.

```bash
# Упаковать (пароль спрашивается дважды, без эха)
filedo report.docx secure

# Упаковать и избавиться от оригинала - восстановимо и посложнее
filedo report.docx secure del p:hunter2
filedo report.docx secure wipe p:hunter2

# Вернуть под запечатанным именем или в текущую папку
filedo report.fd-sec unsecure
filedo report.fd-sec unsecure here

# Открыть в нужной программе, не распаковывая
filedo report.fd-sec reveal

# Папка упаковывается в один файл так же и возвращается всем деревом
filedo "Налоги 2025" secure
filedo "Налоги 2025.fd-sec" unsecure to D:\Restored

# Тихий набор: ключ потяжелее, никаких следов выравнивания - но открывает только FileDO
filedo report.docx secure suite2
```

Папка упаковывается целиком - вместе с пустыми подпапками - и целиком восстанавливается: сначала во
временную папку, на своё место она переносится только после проверки каждого файла, и никогда не
восстанавливается внутрь или поверх уже существующей папки (с `-y` - под именем с числовым суффиксом).
Папку, в которой есть junction, символическая ссылка или точка монтирования, программа отклоняет, а не
проходит по ссылке. `del` и `wipe` убирают исходное дерево только после чтения контейнера обратно и только
если папка не менялась с момента упаковки. `reveal` открывает один файл, поэтому контейнер папки он
отклоняет и указывает на `unsecure`.

`suite2` запечатывает один файл (не папку) набором 2 вместо набора 1 по умолчанию: ключ Argon2id на 256 МиБ
со свёрткой через перец и XChaCha20-Poly1305 кадрами по 64 КиБ, так что файл - шум с первого байта, без
даже того узора длины по кластерам в 512 байт, который есть у набора 1. Он хранит настоящее имя, реальный
размер и время шифрования, но не собственные отметки времени оригинала - восстановленный файл получает
текущее время. Открывает его только FileDO начиная с этой версии: старые сборки FileDO сообщат о
повреждении или неверном пароле, а приложения FastMediaSorter его не откроют, поэтому по умолчанию остаётся
набор 1. `unsecure`, `reveal`, `fdsec info` и `fdsec verify` определяют набор сами; больше ничего не
меняется, и пустой пароль по-прежнему лишь маскировка.

Пять вещей сказаны прямо, потому что функция безопасности, которая себя переоценивает, хуже, чем никакой:

- **Пустой пароль - это только маскировка, без секретности.** Он принимается, и каждая поверхность,
  которая берёт пароль, говорит, чего он стоит, прямо во время ввода.
- **`wipe` снижает шансы на восстановление и ничего не обещает.** На SSD и на файловых системах с
  копированием при записи или журналированием затирание на месте не гарантирует, что старые блоки исчезли.
- **Раскрытая копия живёт в `%LOCALAPPDATA%\FileDO\reveal`**, только для чтения и только для этой учётной
  записи и системы. Она убирается, когда вы скажете, или когда её отпустит открывшая её программа.
- **`unsecure start` - то есть двойной клик - кладёт свою копию в ту же защищённую папку**, а не
  рядом с контейнером, и убирает её при закрытии окна консоли. Эта копия - ваш собственный файл, а
  не версия только для чтения; если программа всё ещё держит её открытой в этот момент, копию
  подметёт следующий запуск FileDO. Насовсем файл возвращает обычный `unsecure`.
- **После сбоя питания эта копия останется на диске до следующего запуска FileDO**, который её подметает.
  Больше её не уберёт ничто.

Ключа восстановления нет: забытый пароль - это потерянный файл. Оригинал остаётся на месте, пока вы не
попросите его убрать, и ничего не удаляется до того, как контейнер записан, перечитан и проверен.
Программы и скрипты никогда не запускаются из контейнера - они извлекаются, и показывается их место.

В окне группа **Защита** несёт те же три операции в виде страниц: пароль скрыт, при упаковке вводится
дважды и передаётся `filedo.exe` незаметно - он не попадает ни в командную строку, ни в отчёт о запуске,
ни в файл истории. Двойной клик по `.fd-sec` этого окна не открывает - он выполняет **Unsecure and start**
в консоли, точно как одноимённый пункт меню Проводника.

## Ключевые возможности

### **Обнаружение поддельной ёмкости**
- **100-файловая проверка** с 1% ёмкости каждый
- **Случайная позиционная проверка** - каждый файл проверяется в уникальных случайных позициях
- **Защита от сложных подделок** - побеждает контроллеры, сохраняющие предсказуемые позиции данных
- **Читаемые паттерны** - использует `ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789` для лёгкого обнаружения повреждений
- **Быстрое зондирование** (`probe`) - 32 маркера через прямой доступ к LBA, завершается за ~1 мин (нужны права администратора)

### **Тестирование производительности**
- Измерение реальной скорости чтения/записи
- Оптимизированная потоковая передача для больших файлов
- Отслеживание прогресса с расчётом ETA
- Настраиваемые размеры файлов (1МБ до 10ГБ)

### **Управление дубликатами файлов**
- **Встроенное обнаружение дубликатов** - интегрировано в основное приложение
- **Несколько режимов выбора** (старейший/новейший по времени создания, алфавитный)
- **Гибкие действия** (удалить/переместить дубликаты) - о каждом файле спрашивается, если не указан `-y` (или `--yes`); запуск без консоли и без `-y` отклоняется до того, как что-либо тронуто
- **Группировка по SHA-256 и побайтовое сравнение с оставляемой копией** непосредственно перед каждым удалением или перемещением; хеш, из кэша или свежий, никогда не единственное доказательство, а перемещение никогда не заменяет существующий файл, в том числе на другой диск
- **Жёсткие ссылки и второе имя того же файла** не считаются дубликатами; корень диска или общей папки, Windows, Program Files и системный TEMP требуют набранного подтверждения даже с `-y`, а сканирование пропускает Windows и Program Files, если не начато внутри них
- **Кэширование хешей** для более быстрых повторных сканирований - кэш (`hash_cache.json`) хранится в `%LOCALAPPDATA%\FileDO\state\`, и хеш из него используется, только пока размер, время изменения, идентификатор файла и время последней смены (change time) совпадают
- **Сохранение/загрузка списков дубликатов** для пакетной обработки
- **Модульная архитектура** с выделенным пакетом fileduplicates

### **Операции копирования**
- **Отслеживание прогресса** с детальными расчётами ETA
- **Защита таймаутом** для повреждённых/медленных файловых систем (3-секундный таймаут)
- **Сохранение метаданных** - права доступа и времена изменения файлов
- **Надёжная обработка ошибок** - продолжает копирование даже при сбоях отдельных файлов
- **Универсальная поддержка** - работает с устройствами, папками, сетевыми ресурсами и отдельными файлами

### **Операции очистки**
- **Только содержимое** - удаляется всё внутри папки, а сама папка остаётся - со своими правами доступа, владельцем, шифрованием, сжатием и атрибутами
- **Честный итог** - то, что удалить не удалось (занято, заблокировано, нет доступа), выводится списком, код выхода 2
- **Универсальная совместимость** - поддерживает устройства (`device D: wipe` всегда означает `D:\`), папки и сетевые ресурсы
- **Защита от ошибок** - корни дисков и ресурсов в любом написании, а также папки TEMP, профиля, Windows, Program Files и FileDO вместе со всеми папками над ними всегда требуют ввода подтверждения, и `--force` его не отменяет; соединение (junction) или символическая ссылка отклоняются сразу

### **Функции безопасности**
- **Высокоскоростное безопасное удаление данных** для предотвращения восстановления
- **Операции заполнения** с оптимизированным управлением буферами
- **Пакетная обработка** для нескольких целей
- **Комплексная история операций** с JSON логированием
- **Контекстное прерывание** - поддержка изящной отмены

## GUI Приложение

**FileDO GUI** (`filedo_win.exe`) - оболочка на VB.NET (Windows Forms): слева перечень заданий, на каждое задание своя нумерованная страница - что обрабатывать, какие параметры, затем проверка и запуск - плюс страница **«Команда»**, экспертный конструктор, который соберёт и запустит **любую** команду FileDO. Что есть в окне:

- **5 языков интерфейса** (EN / RU / UA / DE / FR, запоминается) и **панель помощи**: что делает операция и флаги, какой будет итог, и пример для цели
- **Выбор цели** (устройство / папка / сеть / файл); для **устройства** путь становится **выбором буквы диска**, а выбор системного диска поясняет перенаправление в `%TEMP%\FileDO_Operations`
- **Все операции** на странице «Команда», в одном списке: info, speed, test, fill, clean, cd (дубликаты), всё семейство copy (copy / fastcopy / synccopy / balanced / maxcopy / smartcopy / safecopy), wipe, compare, check, probe, recover, from, hist
- **Источник и назначение** для copy и compare
- **Флаги по контексту** (max, del, nodel, short, hist, `--force` для wipe) и правила удаления для дубликатов/сравнения
- **Страница на задание** в окне по умолчанию - ёмкость, скорость, сведения, проверка повреждённых файлов, прямая проверка, восстановление, дубликаты, сравнение, очистка, копирование, заполнение, стирание и три задания для секретных файлов - и на каждой все опции, какие принимает CLI, включая все двадцать девять флагов `check`
- **Живой предпросмотр** в редактируемом поле на странице «Команда» - правьте вручную всё, что не покрыл конструктор
- Кнопки **Browse** для путей, **Copy command** в буфер и **RUN** в окне консоли
- Находит `filedo.exe` рядом с собой или в `PATH` (работает и в пакете Store, и в портативном zip)
- **Страница «О программе»**: сборка, автор и ссылки на сайт, исходный код, трекер проблем, страницу приватности и другие программы автора
- **Отправить логи автору** - единственная кнопка на этой странице собирает найденные на машине логи FileDO в один zip, открывает папку с выделенным файлом, копирует путь в буфер обмена и открывает вашу почтовую программу с уже заполненным адресом и темой. Zip вы сначала видите сами, и ничего не уходит, пока вы сами не отправите письмо

```powershell
filedo_win              # если в PATH (winget / Store)
filedo_win.exe          # рядом с filedo.exe в портативном zip
```

Страницы **«Защита»** работают с секретными файлами `.fd-sec` - сделать файл секретным, вернуть оригинал или открыть его без распаковки. Пароль скрыт маской и никогда не попадает в командную строку. Если передать окну путь к `.fd-sec` напрямую, оно откроется на странице этого контейнера (`filedo_win.exe C:\a\x.fd-sec`); двойной щелчок в Проводнике окно вообще не задействует - он выполняет **Unsecure and start** в консоли, как описано выше. «История», «Настройки» и «О программе» имеют собственные страницы; прежнее окно-конструктор команд выведено из употребления, а командную строку вручную пишут на странице **«Команда»**.

**Едет везде:** GUI входит в пакет winget, портативный zip, MSI и является плиткой пакета Microsoft Store (MSIX).

## Важные замечания

> **Обнаружение поддельной ёмкости**: Создаёт 100 файлов (по 1% ёмкости каждый) с **поддержкой контекстного прерывания**. Использует современные случайные паттерны проверки и оптимизированное управление буферами для надёжного обнаружения.

> **Улучшенное прерывание**: Все долгие операции поддерживают **изящную отмену Ctrl+C** с автоматической очисткой. Контекстные проверки прерывания в оптимальных точках для немедленной отзывчивости.

> **Безопасное удаление**: `fill <size> del` перезаписывает свободное место с оптимизированным управлением буферами и контекстной записью для безопасного удаления данных.

> **Тестовые файлы**: Создаёт файлы `FILL_*.tmp` и `speedtest_*.txt`. `clean` удаляет только те, что записал FileDO, - с его именами и его содержимым, больше ничего, - сначала показав список и спросив; `--yes` отвечает на вопрос.

> **Общие пакеты**: `fileduplicates` (поиск дубликатов), `fsx` (идентичность путей и атомарная запись без замены) и `statedir` (корень состояния, `%LOCALAPPDATA%\FileDO\state`).

## Технические детали

### Архитектура
- **Модульный дизайн**: Разделен на специализированные пакеты для лучшей поддерживаемости
- **Контекстные операции**: Все долгие операции поддерживают изящную отмену
- **Единый интерфейс**: Общий интерфейс `Tester` для всех типов накопителей
- **Оптимизация памяти**: Потоковые операции с оптимизированным управлением буферами
- **Кроссплатформенность**: Основная поддержка Windows с портируемой кодовой базой Go

### Структура пакетов
```
FileDO/
├── main.go                    # Точка входа приложения
├── fsx/                      # Идентичность путей и атомарная запись
├── statedir/                 # Где лежат файлы состояния (%LOCALAPPDATA%\FileDO\state)
├── fileduplicates/           # Управление дубликатами файлов
│   ├── types.go              # Интерфейсы обнаружения дубликатов
│   ├── duplicates.go         # Основная логика дубликатов
│   ├── duplicates_impl.go    # Детали реализации
│   └── worker.go             # Фоновая обработка
├── filedo_win_vb/           # GUI приложение VB.NET
│   ├── FileDOGUI.sln        # Решение Visual Studio
│   ├── Program.vb           # Точка входа; окно - ShellForm.vb
│   └── bin/                 # Скомпилированный GUI исполняемый файл
├── command_handlers.go       # Обработка команд
├── device_windows.go         # Операции с устройствами
├── folder.go                 # Операции с папками
├── network_windows.go        # Операции с сетевыми накопителями
├── interrupt.go              # Обработка прерываний
├── progress.go               # Отслеживание прогресса
├── main_types.go             # Устаревшие определения типов
├── history.json              # История операций
└── hash_cache.json           # Кэш хешей для дубликатов
```

### Ключевые возможности
- **Улучшенный InterruptHandler**: Потокобезопасное прерывание с поддержкой контекста
- **Оптимизированное управление буферами**: Динамическое изменение размера буферов для оптимальной производительности
- **Комплексное тестирование**: Обнаружение поддельной ёмкости со случайной проверкой
- **Обнаружение дубликатов**: Сравнение файлов по SHA-256 с кэшированием и побайтовая проверка перед любым удалением или перемещением
- **Пакетная обработка**: Выполнение скриптов с обработкой ошибок
- **Ведение истории**: Отслеживание операций на основе JSON
