## Швидкий старт

### Найчастіші завдання

```bash
# Перевірити підробку USB/SD карти
filedo E: test del

# Тест продуктивності диска
filedo C: speed 100

# Безпечне очищення вільного місця
filedo D: fill 1000 del

# Пошук та управління дублікатами
filedo C: check-duplicates
filedo D:\Photos cd old del

# Копіювання з відстеженням прогресу
filedo folder C:\Source copy D:\Backup
filedo device E: copy F:\Archive
# Спершу порахувати дерево заради точного часу, що лишився (інакше копіювання починається з першого файлу)
filedo folder C:\Source copy D:\Backup --precount

# Швидке очищення папок
filedo folder C:\Temp wipe
filedo folder D:\Cache w

# Показати інформацію про диск
filedo C: info
```

### Порівняння тек і очищення

`compare <source> <target> --strict` перевіряє збіг дерев: однакові відносні шляхи, розміри й час зміни дають `Passed` (код 0); відмінність дає `Failed` (код 1); неповне порівняння дає `Not proven` (код 2). Додайте `--by-hash`, щоб порівнювати пари однакового розміру за вмістом замість часу. Звичайний `compare` і далі повідомляє відмінності з `Done` (код 0); `--strict` не можна поєднувати з видаленням. Обидва режими передають `onlyInSource`, `onlyInTarget`, `differentFiles`, `sameFiles`, `totalSource` і `totalTarget` у результаті `--events`. Для `check` обмеження `--max-files N` дозволяє читати щонайбільше N файлів (0 знімає обмеження); `--resume` завершується з `Passed` (код 0), коли кожен відповідний файл має незмінений запис у хорошому списку: `checkedFiles = 0`, а `skippedGoodFiles` показує раніше перевірені файли.

```bash
# Порівняти дві теки і зберегти звіт
filedo compare D:\Data E:\Backup

# Порівняти і видалити (перманентно, без підтвердження)
filedo cmp D:\Data E:\Backup del source  # видалити в Source, якщо є в Target
filedo cmp D:\Data E:\Backup del target  # видалити в Target, якщо є в Source
filedo cmp D:\Data E:\Backup del old     # видалити старіший (mtime), рівні: пропустити
filedo cmp D:\Data E:\Backup del new     # видалити новіший (mtime), рівні: пропустити
filedo cmp D:\Data E:\Backup del small   # видалити менший, рівні: пропустити
filedo cmp D:\Data E:\Backup del big     # видалити більший, рівні: пропустити
 
# Необов'язковий бік (обмеження за стороною)
filedo cmp D:\Data E:\Backup del small source  # тільки якщо менший на Source
filedo cmp D:\Data E:\Backup del big target    # тільки якщо більший на Target
filedo cmp D:\Data E:\Backup del old target    # тільки якщо старіший на Target
filedo cmp D:\Data E:\Backup del new source    # тільки якщо новіший на Source
filedo cmp D:\Data E:\Backup del source --yes  # без питання (скрипти); перевірки лишаються
```

Примітки: зіставлення за відносним шляхом; `del source` і `del target` видаляють пару, лише якщо збігаються розмір і час зміни (`--by-hash` - збігається вміст; `--allow-mismatch` - будь-яку пару), а пара, що не збіглася, виводиться і лишається; два написання однієї папки або папка всередині іншої відхиляються; кожне правило видалення спершу показує, скільки файлів і за яким режимом буде видалено, і питає `(y/N)` - `--yes` (або `-y`) пропускає питання, але не перевірки, а без відповіді (закритий stdin, скрипт) нічого не видаляється і код виходу 2; mtime для old/new; у Windows без урахування регістру, а видалення йде за справжнім ім'ям файлу; якщо щось не вдалося прочитати чи видалити, код виходу 2; логи: compare_report_*.log, delete_report_<mode>_*.log.

### Перевірка читання (check)

`filedo check <тека>` читає файли й позначає пошкодженим той, що читається повільно (> 2.0с) або з помилкою пристрою. Списки пошкоджених і «добрих» файлів лежать у `%LOCALAPPDATA%\FileDO\state` і називають файл шляхом, розміром, часом зміни, томом і самим файлом, на якому його записано: змінений файл або копія за тим самим шляхом на іншій картці під тією ж літерою диска читається знову; записам старих версій без тому не довіряють. Файл «лише в мережі» (заглушка OneDrive чи іншої хмари або файл offline) ніколи не відкривається - ні під час обходу, ні коли перевіряють саме його, - тож нічого не завантажується. Він рахується як `not-read(online-only)`, ніколи не записується в пошкоджені й робить запуск «не вдалося перевірити» (код 2), якщо не знайдено пошкодженого файлу (код 1).

### Встановлення

#### Варіант 1 - winget (рекомендовано)

```powershell
winget install SerZhyAle.FileDO
```

Встановлює інструменти командного рядка (`filedo`, `filedo_check`, `filedo_fill`, `filedo_test`) та графічне вікно `filedo_win` (сторінка на кожне завдання), і додає їх у `PATH`.

Також є в [Microsoft Store](https://apps.microsoft.com/detail/9PH1LPCMRG83) - ті самі інструменти, встановлення й оновлення бере на себе Store.

#### Варіант 2 - Інсталятор (setup EXE)

Завантажте `FileDO-<версія>-setup.exe` з [релізів](https://github.com/SerZhyAle/FileDO/releases/latest) і запустіть. Саме цей варіант робить FileDO звичайною програмою Windows, а не текою з виконуваними файлами:

- ставить файли в `C:\Program Files\FileDO` і додає `filedo` до системного `PATH`;
- створює **пункт у меню «Пуск»** та **піктограму на робочому столі** для вікна FileDO (`filedo_win.exe`) і другий пункт у меню «Пуск», **FileDO Disk Manager**, що одразу відкриває Диспетчер дисків (`filedo_win.exe --disks`);
- реєструє **інтеграцію з Провідником**: групу `File DO..` у контекстному меню будь-якого файлу - Secure (лишити, видалити чи затерти оригінал, або випадкова назва контейнера), Unsecure (за бажанням видалити контейнер або одразу запустити відновлений файл), Wipe this file, Check this file, Info - і тип документа `.fd-sec` із власною піктограмою: подвійний клік - це рівно пункт Unsecure and start: консоль запитує пароль, відновлює оригінал під його справжнім ім'ям у `%LOCALAPPDATA%\FileDO\reveal` - теку, доступну лише цьому обліковому запису та системі, - передає тій програмі, якій належить його справжнє розширення, і прибирає цю копію, коли вікно консолі закривається. У Windows 11 група - у «Показати додаткові параметри»;
- реєструє **тип контейнера диска .fdd** (компонент *Disk container files (.fdd)*): власну піктограму, подвійний клік, що відкриває вікно FileDO і підключає віртуальний диск, і пункти *Mount read-only* та *Unmount* у контекстному меню - див. розділ «Віртуальні диски» нижче.

Інсталятор не має цифрового підпису, тому під час першого запуску Windows може показати «Windows захистила ваш ПК», а потім запросити права адміністратора. Звірте SHA256 (файл `.sha256` опубліковано поруч із завантаженням; `certutil -hashfile FileDO-<версія>-setup.exe SHA256`), потім виберіть «Докладніше» та «Усе одно запустити». Чому попередження з'являється, навіщо потрібні права адміністратора і чого FileDO ніколи не робить: [Windows попередила про FileDO](https://serzhyale.github.io/FileDO/guides/install-trust.html).

Останні три - компоненти, які можна зняти на сторінці «Choose what to install» інсталятора й увімкнути або вимкнути пізніше через **«Змінити»** в «Програми та можливості». Для розгортання без запитань:

```powershell
# усе одразу, мовчки
FileDO-<версія>-setup.exe /quiet
# ..із журналом, якщо потім доведеться пояснювати результат
FileDO-<версія>-setup.exe /quiet /log install.log
# прибрати назад
FileDO-<версія>-setup.exe /uninstall
```

У тому ж релізі публікується і голий `FileDO-<версія>-windows-x64.msi` - саме цей файл лежить усередині setup EXE - для засобів розгортання, яким потрібен пакет та імена компонентів безпосередньо:

```powershell
msiexec /i FileDO-<версія>-windows-x64.msi /qn ADDLOCAL=Main,ExplorerIntegration,DiskContainerIntegration,DesktopShortcut
msiexec /i FileDO-<версія>-windows-x64.msi /qn ADDLOCAL=Main   # без пунктів Провідника, типу .fdd і піктограми
```

Видалення програми прибирає все, що записав інсталятор, включно із записами реєстру.

#### Варіант 3 - Microsoft Store (MSIX)

Один пакет, два входи: плитка **FileDO** - графічний інтерфейс зі сторінкою на кожне завдання, чия сторінка «Команда» збере й запустить будь-яку команду, і команда `filedo` у `PATH` для будь-якого терміналу. У збірці зі Store пунктів Провідника **немає**: пакетна збірка отримує їх лише через підписаний обробник оболонки, а це окрема робота. Тип файлу `.fd-sec` вона **призначає**: подвійне клацання контейнера відкриває вікно FileDO на сторінці «Відкрити секретний файл» з уже вибраним контейнером, і пароль запитується там. Тип .fdd вона теж призначає, але підключати віртуальні диски збірка зі Store не може: подвійне клацання відкриває вікно FileDO на цьому контейнері, де його можна прочитати, перевірити й вивантажити - див. розділ «Віртуальні диски» нижче.

#### Варіант 4 - Ручне завантаження

1. **Завантажте** `FileDO-<версія>-windows-x64.zip` з [релізів](https://github.com/SerZhyAle/FileDO/releases/latest) та розпакуйте куди завгодно.
2. **GUI**: в архіві є `filedo_win.exe` - запускайте поруч з `filedo.exe` для графічного вікна (сторінка на кожне завдання і сторінка «Команда»).
3. **Запуск**: з командного рядка або через GUI.

#### Інтеграція з Провідником без інсталятора

winget, переносний архів і `go install` не запускають інсталятор, тому не реєструють нічого. Ту саму групу й той самий тип документа можна попросити самому - і забрати назад так само:

```powershell
filedo fdsec register              # для цього користувача
filedo fdsec register -all-users   # для всієї машини (потрібна консоль з правами адміністратора)
filedo fdsec unregister            # прибирає рівно те, що було записано
```

FileDO видаляє лише позначене як своє: тип документа, який тим часом почав належати іншій програмі, лишається недоторканим, а той, хто володів `.fd-sec` до FileDO, отримує його назад. Машину, де вже є реєстрація інсталятора, команда теж не чіпає - копія для користувача показувала б кожен пункт двічі.

## Секретні файли (`.fd-sec`)

Один файл - або одна тека, усе її дерево - іде в один контейнер під паролем і повертається назад - із
командного рядка, з меню Провідника або зі сторінок групи **Захист** у вікні. Справжнє ім'я оригіналу,
його реальний розмір і позначки часу запечатані всередині, а в теки - ще шлях, розмір і час кожного
елемента; сам контейнер видає лише власний розмір, своє видиме ім'я та позначки часу (`rename` робить
безіменний блок даних). За вмістом на диску контейнер теки не відрізнити від контейнера файлу.

```bash
# Запакувати (пароль запитується двічі, без відлуння)
filedo report.docx secure

# Запакувати й позбутися оригіналу - з можливістю відновлення і складніше
filedo report.docx secure del p:hunter2
filedo report.docx secure wipe p:hunter2

# Повернути під запечатаним іменем або в поточну теку
filedo report.fd-sec unsecure
filedo report.fd-sec unsecure here

# Відкрити в потрібній програмі, не розпаковуючи
filedo report.fd-sec reveal

# Тека пакується в один файл так само й повертається всім деревом
filedo "Податки 2025" secure
filedo "Податки 2025.fd-sec" unsecure to D:\Restored

# Тихий набір: важчий ключ, жодних слідів вирівнювання - але відкриває лише FileDO
filedo report.docx secure suite2
```

Тека пакується цілком - разом із порожніми підтеками - і цілком відновлюється: спочатку в тимчасову теку,
на своє місце вона переноситься лише після перевірки кожного файлу, і ніколи не відновлюється всередину
або поверх наявної теки (з `-y` - під ім'ям із числовим суфіксом). Теку, у якій є junction, символічне
посилання чи точка монтування, програма відхиляє, а не йде за посиланням. `del` і `wipe` прибирають
вихідне дерево лише після зчитування контейнера назад і лише якщо тека не змінювалася від пакування.
`reveal` відкриває один файл, тому контейнер теки він відхиляє й вказує на `unsecure`.

`suite2` запечатує один файл (не теку) набором 2 замість типового набору 1: ключ Argon2id на 256 МіБ зі
згорткою через перець і XChaCha20-Poly1305 кадрами по 64 КіБ, тож файл - шум із першого байта, без навіть
того візерунка довжини за кластерами в 512 байт, який має набір 1. Він зберігає справжнє ім'я, реальний
розмір і час шифрування, але не власні позначки часу оригіналу - відновлений файл отримує поточний час.
Відкриває його лише FileDO починаючи з цієї версії: старі збірки FileDO повідомлять про пошкодження чи
хибний пароль, а застосунки FastMediaSorter його не відкриють, тому типовим лишається набір 1. `unsecure`,
`reveal`, `fdsec info` і `fdsec verify` визначають набір самі; більше нічого не змінюється, і порожній
пароль, як і раніше, лише маскування.

П'ять речей сказано прямо, бо функція безпеки, яка себе переоцінює, гірша за жодну:

- **Порожній пароль - це лише маскування, без таємниці.** Його приймають, і кожна поверхня, яка бере
  пароль, каже, чого він вартий, просто під час введення.
- **`wipe` знижує шанси на відновлення і нічого не обіцяє.** На SSD і на файлових системах із копіюванням
  під час запису чи журналюванням затирання на місці не гарантує, що старі блоки зникли.
- **`wipe` ніколи не затирає файл, що має інше жорстке посилання.** Затирання на місці сягає кожного імені
  файлу, тому оригінал лишається, і програма про це каже; спершу приберіть зайві посилання або скористайтеся
  `del`.
- **Розкрита копія живе в `%LOCALAPPDATA%\FileDO\reveal`**, лише для читання і лише для цього облікового
  запису та системи. Вона зникає, коли ви скажете, або коли її відпустить програма, що її відкрила.
- **`unsecure start` - тобто подвійний клік - кладе свою копію в ту саму захищену теку**, а не поруч
  із контейнером, і прибирає її, коли закривається вікно консолі. Ця копія - ваш власний файл, а не
  версія лише для читання; якщо програма ще тримає її відкритою в цю мить, копію прибере наступний
  запуск FileDO. Назавжди файл повертає звичайний `unsecure`.
- **Після збою живлення ця копія залишиться на диску до наступного запуску FileDO**, який її прибирає.
  Більше її не прибере ніщо.

Ключа відновлення немає: забутий пароль - це втрачений файл. Оригінал залишається на місці, доки ви не
попросите його прибрати, і нічого не видаляється до того, як контейнер записано, перечитано й перевірено.
Програми та скрипти ніколи не запускаються з контейнера - їх видобувають і показують їхнє місце.

У вікні група **Захист** несе ті самі три операції у вигляді сторінок: пароль прихований, під час
пакування вводиться двічі й передається `filedo.exe` непомітно - він не потрапляє ні в командний рядок,
ні у звіт про запуск, ні у файл історії. Подвійний клік на `.fd-sec` це вікно не відкриває - він виконує
**Unsecure and start** у консолі, так само як однойменний пункт меню Провідника.

## Віртуальні диски (`.fdd`)

Контейнер - це звичайний файл `.fdd`, у якому лежить цілий том. Підключений, він стає літерою диска, як
будь-який інший; відключений - це файл, який можна копіювати, зберігати в резервній копії й читати самим
FileDO, не підключаючи. Формат опубліковано повністю - як контракт `FDD-FORMAT`, а те, що мусить робити
програма, яка його читає чи пише, - як `FDD-BEHAVIOUR`, - тож дані не залежать від того, чи лишиться FileDO.

```bash
# Створити контейнер на 20 ГБ (plain: файл росте в міру запису) і підключити його
filedo vd new work.fdd 20G
filedo work.fdd mount

# Зберегти, позначити коректно закритим, відключити
filedo X: unmount

# Зашифрований: vault завжди запитує пароль (двічі)
filedo vd new private.fdd 5G vault

# Прочитати без підключення - без прав адміністратора, у контейнер нічого не пишеться
filedo work.fdd info
filedo work.fdd verify
filedo work.fdd export D:\work.vhd vhd

# Змінити, поки він не підключений
filedo work.fdd grow 40G
filedo private.fdd pass
filedo private.fdd clone open-copy.fdd nopass
```

Чотири профілі для `vd new`: `plain` росте в міру заповнення, `fast` одразу займає весь розмір, `ram` тримає
том у пам'яті, поки він підключений, і зберігає його у файл кожні кілька секунд (збій втрачає все, що
записано після останнього збереження), а `vault` завжди зашифрований. `seal` пише копію лише для читання
назавжди, `clone` - записувану копію з власним ідентифікатором, `compact` повертає диску невикористане
місце файлу. `format` стирає том (`fs ntfs` або `fs exfat`), а `destroy` видаляє файл контейнера (`wipe`
спершу його затирає): обидва спочатку питають і обидва відмовляються працювати з підключеним контейнером -
цю заборону не знімає жоден ключ. `chkdsk` перевіряє том усередині непідключеного контейнера й нічого не пише, а `chkdsk fix` запускає для нього `chkdsk /f` - виправлення для контейнера, закритого некоректно, - і спочатку питає. `vd add work.fdd as work` дає контейнеру коротке ім'я, `vd list` і
`vd status` показують, що відомо і що підключено, а `vd auto work logon` підключає замаскований контейнер
під час входу до Windows. `vd guard on` вмикає сторож вимкнення: коли сеанс закінчується - вимкнення,
перезавантаження чи вихід із системи, але не сон, - він спершу зберігає диски `ram`, а потім відключає всі
підключені контейнери, щоб кожен був закритий чисто; `vd guard status` показує його останній запуск. Файли
`.vhd`, `.vhdx` та `.iso` підключаються засобами самої Windows:
`filedo disk.vhdx mount`.

Два слова, дві різні обіцянки, і FileDO ніколи їх не плутає:

- **Без пароля контейнер замаскований, а не зашифрований.** Маскування ховає том від випадкового погляду
  й від програм, які шукають образи дисків, - і ні від кого, хто має файл і FileDO. `info` каже, який із
  двох випадків перед вами.
- **З паролем він зашифрований**: без пароля файл не прочитати. Відновлення немає - забутий пароль означає
  втрачений контейнер. `pass` змінює пароль, не переписуючи дані, тому копії файлу, зроблені раніше, і
  далі відкриваються старим паролем.
- **Пароль ніколи не знімається на місці.** Порожній новий пароль відхилено; натомість
  `clone <new.fdd> nopass` пише замасковану копію, а зашифрований оригінал лишається як був.
- **Шифрування захищає файл, а не підключений том.** Поки том підключений, його читає будь-яка програма,
  яку ви запускаєте, як будь-який інший диск. `export` зашифрованого контейнера теж не зашифрований, а
  `ram` з паролем дозволяє Windows вивантажити незашифровані дані у файл підкачки.
- **`verify` читає, але не доводить.** Він читає заголовки, карту й кожен зайнятий кластер і повідомляє
  про пошкодження (код 4), але формат 1.0 не зберігає контрольних сум даних, тому дані прочитано, але не
  звірено.

Що потрібно від платформи, прямо:

- **Лише Windows.** Літеру диска дає вбудований у Windows ініціатор iSCSI, який говорить із блоковим
  сервером усередині `filedo.exe`; сервер слухає лише адресу 127.0.0.1 - ніщо не залишає цей комп'ютер, і
  контейнер ніколи не потрапляє в жодну мережу - хіба що ви самі відкриєте до нього спільний доступ (нижче).
- **Підключення потребує прав адміністратора.** `mount`, `unmount`, `save`, `format`, `chkdsk` і `vd auto` просять у
  Windows згоду адміністратора на крок з ініціатором; пароль туди не передається, а сам блоковий сервер
  ніколи не працює з підвищеними правами. Пакетний файл такого запиту не показує - запускайте його з
  консолі адміністратора. Якщо службою «Ініціатор iSCSI (Microsoft)» скористатися не можна, запуск
  закінчується кодом 7, і нічого не підключено.
- **Збірка з Microsoft Store не може підключати диски.** Запакований застосунок не може ні налаштувати
  ініціатор iSCSI, ні попросити права адміністратора, тому там `mount`, `unmount`, `save`, `format`, `chkdsk`,
  `vd auto`, `vd guard` і `vd register` закінчуються кодом 6. `info`, `verify`, `export`, `compact`, `grow`, `seal`,
  `clone`, `pass`, `destroy`, `vd new`, `vd list`, `vd status`, `vd add` і `vd forget` працюють і там; для
  підключення встановіть інсталятор або переносну збірку з GitHub.
- **Підключення переживає вікно.** Якщо закрити вікно FileDO, диск і його сервер лишаються, а нове вікно
  знову показує їх у списку; відключайте в Диспетчері дисків, на сторінках групи «Диски» або командою `filedo X: unmount`.

У **Диспетчері дисків** виберіть зареєстрований файловий диск і **«Поділитися через Fast Media Sorter & Sharing..»** у панелі відомостей або меню «Ще» (`Ctrl+Shift+S`). Спочатку запустіть Share Manager цієї програми. Якщо worker недоступний, діалог пропонує повторну перевірку та [сторінку встановлення](https://serzhyale.github.io/FastMediaSorter_Lite/); недоступність worker не означає відсутності програми. За потреби увімкніть додатковий компонент дисків FileDO. Настільний інсталятор не підписано. Типово доступ на читання і запис, «лише для читання» вмикається галочкою; sealed-диск завжди доступний лише для читання. Укажіть назву папки та за бажанням відкрийте її сполученим пристроям. Уже підключений у FileDO диск відключається безпечно після підтвердження; RAM зберігається штатним відключенням. Якщо ввімкнено автоматичне підключення FileDO, явно погодьтеся вимкнути його; ручний режим `keep` завершується при відключенні. Автозапуск FMS вмикається окремо. **«Закрити спільний диск»** зберігає реєстрацію; **«Припинити спільний доступ»** видаляє її та ключ автозапуску FMS. При помилці виконані кроки зберігаються: оновіть список, повторіть решту дій або припиніть доступ перед явним відновленням локального підключення та попередньої автоматичної політики. Сполучайте пристрої через Share Manager. Файли передаються через SFTP, ресурс SMB Windows не створюється. Сеансовий режим потребує входу; служба доступна без входу. Диски у розділах та керування зовнішнім worker з неперевіреної збірки Store тут недоступні; використовуйте настільну збірку. Покрокова сторінка - що потрібно, кожен діалог і відновлення - тут: [Спільний доступ до дисків FileDO через Fast Media Sorter](https://serzhyale.github.io/FileDO/guides/fms-sharing.html).

**Спільний доступ до диска через Fast Media Sorter for Windows (за бажанням).** Якщо встановлено Fast Media
Sorter for Windows, `vd share work.fdd on` пропонує диск телефонам і планшетам, які ви з нею зв'язали, як ще
одну теку; `vd open`, `vd close` і `vd autostart` відкривають його для них, закривають і відкривають знову
після перезапуску. FileDO не відкриває для цього мережевих з'єднань - він говорить із тією програмою через
локальний канал, а файли віддає вона. Зашифрований диск розблоковується тут, на цьому комп'ютері, і ніколи з
телефона; поки він відкритий, його файли може читати кожен зв'язаний пристрій, а `vd autostart` зберігає його
пароль на цьому комп'ютері, захищеним для тієї програми, доки ви не вимкнете автозапуск, не припините доступ
або не змінете пароль. Спільний диск тримає та програма, тому `mount` відмовляє, поки вона його тримає; `vd
status` каже, хто тримає. Лише серверна редакція Fast Media Sorter for Windows тримає спільні диски
доступними, коли ніхто не ввійшов у систему.

Коди виходу однієї команди над контейнером: 0 готово, 2 помилка в команді, 3 хибний пароль,
4 пошкодження, 5 помилка введення-виведення, 6 не підтримується, 7 транспорт недоступний, 8 зайнятий
(підключений, відкритий або заблокований). Пакетний файл зберігає 0/1/2.

У Провіднику компонент інсталятора *Disk container files (.fdd)* (`DiskContainerIntegration`) дає `.fdd`
власну піктограму і три пункти, що відкривають вікно FileDO. Подвійний клік підключає: чистий замаскований
контейнер - одразу; зашифрований запитує пароль у вікні, ніколи не в командному рядку; контейнер, який не
було коректно закрито, спершу каже про це з часом останнього повного збереження і чекає; уже підключений
відкриває свій диск. Контекстне меню додає *Mount read-only* і *Unmount* (у Windows 11 вони в «Показати
додаткові параметри»). Без інсталятора те саме записує `filedo vd register` (додайте `-all-users` для всієї
машини), а `filedo vd unregister` прибирає. У вікні група **«Диски»** має по сторінці на кожну операцію й
називає обидва захисти точно так, як консоль.

**Диспетчер дисків** - друге вікно тієї самої `filedo_win.exe`, а не нова програма, - по рядку на віртуальний диск: диски з вашого списку, диски, підключені зараз, і образи VHD, VHDX або ISO, які підключив FileDO. Рядок показує стан словами поруч зі значком («Підключений», «Підключений, лише читання», «Підключений, не збережено 180 MiB» для диска `ram`, «Сервер зник - том недоступний», «Образ підключено», «Файл зник», «За цим шляхом інший контейнер», «Не читається», «Закритий некоректно», «Не підключений»), а список сам підтримує актуальність без ручного оновлення. Навколо нього - панель кнопок («Новий диск..», «Додати..», «Підключити», «Відключити», «Відкрити», «Зберегти», «Ще», «Оновити», «Довідка», «Головне вікно»), рядок фільтра і панель подробиць із відповідними кнопками; недоступна кнопка каже, чому, у підказці й у панелі, а збірка з Microsoft Store, яка підключати не може взагалі, ховає елементи підключення, а не робить їх сірими. Подвійний клік або Enter підключає непідключений диск і відкриває том підключеного - ніколи не відключає; перетягніть файли `.fdd` на список, щоб додати їх, а `.vhd`, `.vhdx` або `.iso` - щоб підключити образ після одного підтвердження. «Новий диск..» спершу питає, де диск зберігатиме дані: «Файл на диску..» відкриває сторінку «Створити диск» у головному вікні, «Розділ у вільному місці..» - власний діалог диспетчера для розділу: мапа вільного місця кожного GPT-диска, розмір, профіль, мітка й ім'я (збірка з Microsoft Store пропонує лише файл). Для диска-файлу «Експорт», «Стиснути», «Збільшити», «Запечатана копія», «Клонувати», «Змінити пароль», «Форматувати» і «Знищити» відкривають свою сторінку завдання в головному вікні з уже вибраним контейнером; «Форматувати» і «Знищити» зберігають там підтвердження, яке треба набрати. Рядок [диска-розділу](#диски-розділи) каже «Розділ не підключено» або «Розділ змінився», якщо він не там, де був зареєстрований, пропонує «Образ у файл..», щоб скопіювати його в новий файл `.fdd`, а видаляється він у самому диспетчері: «Знищити» просить набрати його ім'я й може спершу перезаписати розділ. «Прийняти розділ..» (у «Ще» або правим клацанням по порожньому місцю) показує розділи FileDO на дисках цього комп'ютера, яких немає в списку, і додає вибраний під заданим ім'ям; збірка з Microsoft Store ховає «Образ у файл» і «Прийняти розділ».

Відкривається він пунктом **FileDO Disk Manager** у меню «Пуск» (його додає інсталятор; пункт запускає `filedo_win.exe --disks`), кнопкою **«Диспетчер дисків»** праворуч угорі вікна FileDO або першим рядком його групи «Диски» (також **Ctrl+Shift+D**), або командою `filedo_win.exe --disks`; його кнопка **«Головне вікно»** виводить вікно FileDO вперед. **F1** відкриває довідку - що каже рядок, таблиця клавіш, посилання. Під час першого відкриття диспетчера вікно вітання пояснює, що таке віртуальний диск, і каже: *Замаскований, а не зашифрований: його прочитає будь-хто, у кого є цей файл і FileDO. Відкривається без пароля.* *Зашифрований: відкривається лише своїм паролем.* Там же сказано, що згоду адміністратора Windows питає під час кожного підключення й відключення, а для диска-розділу - ще й під час кожного читання, і запропоновано «Створити мій перший диск..», «Додати файл .fdd, який у мене вже є..», «Прочитати посібник на сайті» і «Не зараз». Таблиця клавіш і знімки - у [посібнику з віртуальних дисків](https://serzhyale.github.io/FileDO/guides/virtual-disks.html#manager). Закриття диспетчера ніколи не відключає диск.

### Диски-розділи

Віртуальний диск може жити не лише у файлі, а й у розділі. FileDO створює новий розділ GPT у
нерозподіленому просторі диска й цілком заповнює його одним контейнером; поза цим вільним місцем нічого не
змінюється - FileDO ніколи не перетворює наявний розділ, не змінює його розмір і не пише в нього. Лише диски
GPT: диски MBR, динамічні диски, дискові простори (Storage Spaces), диски iSCSI, знімні та USB-диски
відхиляються, і `vd disks` називає причину для кожного. Ви отримуєте диск, який не тримає жодна файлова
система-господар, якому Windows не дає літеру й не пропонує відформатувати, із заздалегідь закріпленим
місцем; чого ви не отримуєте - то це швидкості.

```bash
# Усі диски, їхні розділи й вільне місце - кожна ділянка придатна чи ні і чому (без прав адміністратора)
filedo vd disks

# Диск-розділ на всю вільну ділянку (рядок create друкує vd disks) з іменем data
filedo vd new part disk:{GPT-GUID} size max at <offset> as data
filedo vd mount data

# Скопіювати його у звичайний файл .fdd, який читається без прав адміністратора
filedo vd image data to D:\data.fdd

# Зареєструвати розділ FileDO, якого цей комп'ютер не знає (диск перенесли з іншого комп'ютера)
filedo vd adopt fdpart:{GUID} as data

# Видалити розділ: для підтвердження наберіть ім'я диска; місце знову стає нерозподіленим
filedo vd destroy data
```

`<disk>` - це `disk:{GUID}` або номер, який надрукував `vd disks`; `size` - `max` або розмір на кшталт
`40G` (округлюється вниз до 1 MiB, не менше 64 MiB). Профіль за замовчуванням - `fast`; `plain`, `vault` і
`ram` теж працюють. Перше підключення форматує том у NTFS. До диска-розділу звертаються за іменем або за
локатором `fdpart:{GUID}`, шляху в нього немає; `mount`, `unmount`, `save`, `info`, `verify`, `export`,
`pass`, `seal`, `clone`, `vd auto` і сторож вимкнення працюють так само, як із файлом, `compact` і `grow` -
ні (розмір розділу сталий), а спільний доступ через Fast Media Sorter поки відхиляється. `vd forget` прибирає
ім'я й лишає розділ на диску; `vd destroy .. wipe` перед видаленням затирає розділ. Відхилений диск
закінчується кодом 6, відмова в згоді - кодом 7, а розмітка, що змінилася відтоді, як її показав список, -
кодом 5, і при цьому нічого не змінено.

- **Згода адміністратора потрібна для кожного читання, а не лише для підключення.** Розділ не можна відкрити
  без прав адміністратора, тому `info`, `verify`, `export`, `pass`, `seal`, `clone` і `vd image` теж просять
  у Windows згоду. `vd image` знімає цю потребу: файл, який він пише, - звичайний `.fdd`, і будь-який шлях
  читання відкриває його без прав адміністратора.
- **Не швидший за файловий диск.** У вимірі від початку до кінця на накопичувачі NVMe диск-розділ виявився
  повільнішим за файл `.fdd` на NTFS. Обирайте його заради окремого закріпленого місця, а не заради швидкості.
- **`fast` перезаписує вільне місце, `plain` і `vault` - ні.** Усе, що раніше лежало у вільному місці,
  лишається в невикористаних кластерах диска-розділу `plain` або `vault`, доки том не запише поверх; `fast`
  перезаписує весь розділ під час створення.
- **«Керування дисками» Windows (`diskmgmt.msc`) і далі показує розділ і може його видалити.** Видалення
  там видаляє й диск усередині, ні про що не питаючи щодо його вмісту. Безпечний шлях - власний `vd destroy`
  FileDO: він відмовляє для підключеного диска, просить набрати ім'я диска й видаляє лише розділ, про який
  довів, що це розділ FileDO.
- **Диски-розділи недоступні у версії з Microsoft Store.** Там `vd disks` каже про це, а кожна команда для
  розділів закінчується кодом 6; використовуйте інсталятор або переносну збірку з GitHub.

## Ключові можливості

### **Виявлення підробної місткості**
- **Тест на 100 файлів** по 1% місткості кожен
- **Випадкова позиційна перевірка** - кожен файл перевіряється в унікальних випадкових позиціях
- **Захист від складних підробок** - перемагає контролери, що зберігають дані в передбачуваних позиціях
- **Читабельні шаблони** - використовує `ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789` для легкого виявлення пошкоджень
- **Швидке сирове зондування** (`probe`) - 32 маркери через прямий доступ до LBA, ~1 хв (потрібен Адмін)

### **Тест продуктивності**
- Вимірювання реальної швидкості читання/запису
- Оптимізований стрімінг для великих файлів
- Відстеження прогресу з розрахунком ETA
- Налаштовувані розміри файлів (1МБ до 10ГБ)

### **Управління дублікатами файлів**
- **Вбудоване виявлення дублікатів** - інтегровано в основну програму
- **Кілька режимів вибору** (найстарший/найновіший за часом створення, алфавітний)
- **Гнучкі дії** (видалити/перемістити дублікати) - про кожен файл запитується, якщо не вказано `-y` (або `--yes`); запуск без консолі й без `-y` відхиляється до того, як щось змінено
- **Групування за SHA-256 і побайтове порівняння із залишеною копією** безпосередньо перед кожним видаленням або переміщенням; хеш, з кешу чи свіжий, ніколи не єдиний доказ, а переміщення ніколи не замінює наявний файл, зокрема на інший диск
- **Жорсткі посилання та друге ім'я того самого файлу** не вважаються дублікатами; корінь диска або спільної папки, Windows, Program Files і системний TEMP вимагають набраного підтвердження навіть з `-y`, а сканування пропускає Windows і Program Files, якщо не розпочате всередині них
- **Кешування хешів** для швидших повторних сканувань - кеш (`hash_cache.json`) зберігається в `%LOCALAPPDATA%\FileDO\state\`, і хеш із нього використовується, лише поки розмір, час зміни, ідентифікатор файлу та час останньої зміни запису (change time) збігаються
- **Збереження/завантаження списків дублікатів** для пакетної обробки
- **Модульна архітектура** з виділеним пакетом fileduplicates

### **Функції безпеки**
- **Високошвидкісне безпечне видалення даних** для запобігання відновлення
- **Операції заповнення** з оптимізованим управлінням буферами
- **Пакетна обробка** для декількох цілей
- **Комплексна історія операцій** з JSON журналюванням
- **Контекстне переривання** - підтримка елегантного скасування

## GUI додаток

**FileDO GUI** (`filedo_win.exe`) - оболонка на VB.NET (Windows Forms): ліворуч перелік завдань, на кожне завдання своя нумерована сторінка - що обробляти, які параметри, далі перевірка та запуск - плюс сторінка **«Команда»**, експертний конструктор, що збере й запустить **будь-яку** команду FileDO. Що є у вікні:

- **5 мов інтерфейсу** (EN / RU / UA / DE / FR, запам'ятовується) та **панель допомоги**: що робить операція й прапорці, який буде підсумок, і приклад для цілі
- **Вибір цілі** (пристрій / папка / мережа / файл); для **пристрою** шлях стає **вибором літери диска**, а вибір системного диска пояснює перенаправлення у `%TEMP%\FileDO_Operations`
- **Усі операції** на сторінці «Команда», в одному списку: info, speed, test, fill, clean, cd (дублікати), усе сімейство copy (copy / fastcopy / synccopy / balanced / maxcopy / smartcopy / safecopy), wipe, compare, check, probe, recover, from, hist
- **Джерело та призначення** для copy і compare
- **Прапорці за контекстом** (max, del, nodel, short, hist, `--force` для wipe) та правила видалення для дублікатів/порівняння
- **Сторінка на завдання** у вікні за умовчанням - ємність, швидкість, відомості, перевірка пошкоджених файлів, пряма перевірка, відновлення, дублікати, порівняння, очищення, копіювання, заповнення, стирання і три завдання для секретних файлів - і на кожній усі опції, які приймає CLI, разом з усіма двадцятьма дев'ятьма прапорцями `check`
- **Живий попередній перегляд** у редагованому полі на сторінці «Команда» - правте вручну все, що не покрив конструктор
- Кнопки **Browse** для шляхів, **Copy command** у буфер і **RUN** у вікні консолі
- Знаходить `filedo.exe` поруч із собою або в `PATH` (працює і в пакеті Store, і в портативному zip)
- **Сторінка «Про програму»**: збірка, автор і посилання на сайт, вихідний код, трекер проблем, сторінку приватності та інші програми автора
- **Надіслати логи автору** - єдина кнопка на цій сторінці збирає знайдені на машині логи FileDO в один zip, відкриває теку з виділеним файлом, копіює шлях у буфер обміну і відкриває вашу поштову програму з уже заповненою адресою та темою. Zip ви спершу бачите самі, і нічого не йде, поки ви самі не надішлете лист

```powershell
filedo_win              # якщо в PATH (winget / Store)
filedo_win.exe          # поруч з filedo.exe у портативному zip
```

Сторінки **«Захист»** працюють із секретними файлами `.fd-sec` - зробити файл секретним, повернути оригінал або відкрити його без розпакування. Пароль приховано маскою, і він ніколи не потрапляє в командний рядок. Якщо передати вікну шлях до `.fd-sec` напряму, воно відкриється на сторінці цього контейнера (`filedo_win.exe C:\a\x.fd-sec`); подвійний клік у Провіднику вікно взагалі не задіює - він виконує **Unsecure and start** у консолі, як описано вище. «Історія», «Налаштування» і «Про програму» мають власні сторінки; попереднє вікно-конструктор команд виведено з ужитку, а командний рядок вручну пишуть на сторінці **«Команда»**. **Диспетчер дисків** - друге вікно для віртуальних дисків, яке відкривають клавішами **Ctrl+Shift+D**, кнопкою праворуч угорі або командою `filedo_win.exe --disks`, - описано в розділі *Віртуальні диски* вище.

**Їде всюди:** GUI входить у пакет winget, портативний zip, MSI і є плиткою пакета Microsoft Store (MSIX).

## Важливі зауваження

> **Виявлення підробної місткості**: Створює 100 файлів (по 1% місткості кожен) з **підтримкою контекстного переривання**. Використовує сучасні випадкові шаблони перевірки та оптимізоване управління буферами для надійного виявлення.

> **Покращене переривання**: Всі довгі операції підтримують **елегантне скасування Ctrl+C** з автоматичним очищенням. Контекстні перевірки переривання в оптимальних точках для миттєвої відповіді.

> **Безпечне видалення**: `fill <розмір> del` перезаписує вільний простір з оптимізованим управлінням буферами та контекстним записом для безпечного видалення даних.

> **Тестові файли**: Створює файли `FILL_*.tmp` та `speedtest_*.txt`. `clean` видаляє лише ті, що записав FileDO, - з його іменами та його вмістом, більше нічого, - спершу показавши список і спитавши; `--yes` відповідає на запитання.

> **Спільні пакети**: `fileduplicates` (пошук дублікатів), `fsx` (ідентичність шляхів і атомарний запис без заміни) та `statedir` (корінь стану, `%LOCALAPPDATA%\FileDO\state`).

- **Покращений InterruptHandler**: Потокобезпечне переривання з підтримкою контексту

- **Комплексне тестування**: Виявлення підробної місткості з випадковою верифікацією
- **Виявлення дублікатів**: Порівняння файлів за SHA-256 з кешуванням і побайтова перевірка перед будь-яким видаленням або переміщенням
- **Пакетна обробка**: Виконання скриптів з обробкою помилок
- **Ведення історії**: Відстеження операцій на основі JSON

## Історія версій

**Ще не випущено** (наступна версія)
- **Віртуальні диски (`.fdd`)**: цілий том в одному файлі, що підключається літерою диска - `filedo vd new`, `mount`, `unmount`, а також `info`, `verify` і `export` (простий образ або VHD) без підключення та `grow`, `compact`, `format`, `seal`, `clone`, `pass`, `destroy`; без пароля контейнер замаскований, з паролем - зашифрований, і одне ніколи не називається іншим
- **Провідник**: новий компонент інсталятора *Disk container files (.fdd)* (`DiskContainerIntegration`) дає `.fdd` піктограму, підключення подвійним кліком і пункти *Mount read-only* / *Unmount*; без інсталятора те саме робить `filedo vd register`
- **GUI**: нова група **«Диски»** - по сторінці на операцію - і **Диспетчер дисків**, друге вікно з рядком на кожен віртуальний диск, станом словами та підключенням, відключенням, відкриттям і збереженням прямо з рядка; підключений диск переживає закриття вікна, а інсталятор додає пункт *FileDO Disk Manager* у меню «Пуск», який відкриває його одразу
- **Обмеження**: лише Windows; підключення просить згоду адміністратора; збірка з Microsoft Store читає, перевіряє й вивантажує контейнери, але підключати їх не може

**v2609241700** (Поточна)
- **Секретні файли (`.fd-sec`)**: один файл пакується в контейнер під паролем і повертається назад - `secure`, `unsecure`, `reveal` - з командного рядка, з меню Провідника або зі сторінок групи Protect у вікні; справжнє ім'я, розмір і дати оригіналу запечатано всередині
- **Інтеграція з Провідником**: інсталятор додає до контекстного меню групу `File DO..` (Secure, Unsecure, Wipe this file, Check this file, Info) і тип документа `.fd-sec`; `filedo fdsec register` / `unregister` робить те саме без інсталятора
- **GUI**: нове вікно - ліворуч перелік завдань, для кожного завдання своя сторінка з усіма параметрами CLI, плюс сторінки Command, History, Settings і About; старе вікно-конструктор команд прибрано
- **Копіювання**: починається з першого файлу; `--precount` спочатку перераховує дерево для точних підсумків і часу, що залишився
- **CLI**: єдині коди виходу - 0 пройдено або виконано, 1 знайдено дефект, 2 перевірити не вдалося; облікові дані вичищаються до запису в історію
- **Поширення**: FileDO є в Microsoft Store; `THIRD-PARTY-NOTICES.txt` входить до zip, MSI і пакета Store
- **Документація**: нові посібники - секретні файли та "Windows warned you about FileDO"
