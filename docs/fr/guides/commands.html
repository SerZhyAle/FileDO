Guide · scripts et agents

Demandez quelque chose au FileDO déjà lancé et lisez sa réponse.

Un script, une tâche planifiée, un raccourci ou un outil de développement tape filedo <commande>. Le programme à fenêtre FileDO déjà lancé fait le travail et répond par un code de sortie. Aucune seconde copie ne s’ouvre.

Les commandes

Dix commandes couvrent ce qu’un script attend de FileDO. La plupart vont au programme à fenêtre en cours d’exécution ; commands et version répondent d’elles-mêmes. Chacune affiche sa réponse et se termine par un code de sortie, sur lequel un script peut se brancher. Toutes sont sûres : elles ne modifient que les fenêtres et les exécutions propres de FileDO et ne lisent aucun de vos fichiers.

Commande Ce qu’elle fait Si FileDO ne tourne pas
filedo commands Liste chaque commande que FileDO accepte ; --json affiche le manifeste lui-même. Fonctionne quand même ; aucune fenêtre ne s’ouvre.
filedo version Affiche le nom du produit, sa version et la version du jeu de commandes. Fonctionne quand même ; aucune fenêtre ne s’ouvre.
filedo status Dit si le programme à fenêtre tourne et est prêt ; indique sa version, son identifiant de processus, ses fenêtres ouvertes et le nombre d’exécutions en cours. Code 11 : rien ne tourne.
filedo show Met la fenêtre principale au premier plan et l’ouvre si le programme tourne sans fenêtre. Démarre FileDO, puis le lui demande.
filedo quit Ferme proprement le FileDO en cours. Une exécution en cours fait refuser la commande (code 11), sauf si --stop-jobs arrête d’abord les exécutions. Rien à fermer : code 0.
filedo disk-manager show Met le Gestionnaire de disques au premier plan et l’ouvre seul quand le programme n’a pas de fenêtre. Démarre FileDO avec le seul Gestionnaire de disques.
filedo settings show Ouvre la page Réglages de la fenêtre principale. Démarre FileDO, puis le lui demande.
filedo tray start Démarre FileDO masqué, avec son icône de notification et sans fenêtre. Le démarre ; une copie déjà en cours reste telle quelle.
filedo job list Liste les exécutions en cours et les opérations en file d’attente du Gestionnaire de disques : fenêtre, verbe, état, étape et pourcentage. La réponse ne contient aucun nom de fichier. Code 11 : rien ne tourne.
filedo job stop Demande aux exécutions de s’arrêter en douceur, comme le bouton Arrêter, vide la file du Gestionnaire de disques et attend qu’il n’en reste aucune. --where all|shell|manager choisit la fenêtre. Rien à arrêter : code 0.
filedo status

Ouvrir un fichier conteneur

Pour ouvrir un disque virtuel .fdd ou un conteneur .fd-sec dans sa propre fenêtre FileDO sans passer la main à une copie déjà lancée, utilisez filedo_win.exe open. Si le conteneur .fdd est déjà monté, l’Explorateur ouvre plutôt son lecteur.

Commande Ce qu’elle fait
filedo_win.exe open --path <file> [--mode mount|mount-ro|unmount] Ouvre le conteneur dans sa propre fenêtre (ou ouvre le lecteur monté) et quitte avec 0 à la fermeture, 10 en cas d’erreur d’appel ou 11 si le fichier n’existe pas.
filedo_win.exe <file>, --mount, --mount-ro, --unmount Anciennes écritures conservées pour le double-clic et le menu de l’Explorateur ; elles lancent la même ouverture sans contrat de code de sortie.
filedo_win.exe open --path C:\v\work.fdd --mode mount-ro

Outils de développement

Les cinq commutateurs que les scripts de build appellent sur le programme à fenêtre sont aussi des commandes, écrites filedo_win.exe <mots>. Elles s’exécutent dans leur propre processus, jamais par une fenêtre en cours d’exécution, et les quatre qui écrivent reçoivent le dossier de destination par --out.

Commande Ce qu’elle fait
filedo_win.exe selftest run Lance le contrôle propre du programme à fenêtre et se termine par le code 0 quand toutes les lignes passent.
filedo_win.exe help-pages build --out <folder> Écrit les pages d’aide de la fenêtre et leurs images, dans chaque langue et les deux thèmes.
filedo_win.exe screens capture --out <folder> Produit les captures d’écran des guides à partir des vraies fenêtres.
filedo_win.exe menu-icons write --out <folder> Écrit les icônes du menu de l’Explorateur et affiche chaque fichier écrit.
filedo_win.exe ui-drive run --out <folder> Pilote les vraies fenêtres à l’écran pour la recette visuelle et écrit ses preuves ; vos propres réglages sont ensuite rétablis.

Le programme à fenêtre n’a pas de console propre ; lisez son code de sortie en l’attendant :

(Start-Process .\filedo_win.exe -ArgumentList 'selftest run' -Wait -PassThru).ExitCode

Lire la réponse

Une commande affiche une phrase pour une personne. Ajoutez --json pour obtenir à la place une ligne JSON avec status, exitCode, reason, message et, quand la commande renvoie quelque chose, data. Un script doit se brancher sur le code de sortie.

Code de sortie Signification
0 Terminé.
1 La commande s’est exécutée mais l’opération a échoué.
2 Non prouvé : le délai est écoulé sans réponse. Le FileDO en cours travaille peut-être encore.
10 Appel incorrect : commande, option ou valeur inconnue, option manquante ou requête trop grande.
11 Pas prêt : FileDO ne tourne pas ou est occupé - une boîte de dialogue est ouverte, il se ferme ou répond à une autre commande.
12 Autorisation : la classe de risque de la commande est désactivée dans les réglages, ou le FileDO en cours est élevé et l’appelant ne l’est pas.

Chacune des dix commandes ci-dessus attend sa réponse un temps limité - de 2 secondes pour filedo status à 60 secondes pour filedo job stop. Relancer l’une d’elles après le code 2 est sans risque : chacune laisse le même état qu’une seule exécution.

filedo status
(filedo job list --json | ConvertFrom-Json).data.jobs.Count
filedo quit --stop-jobs

Ce que d’autres programmes peuvent demander

Chaque commande appartient à l’une de quatre classes de risque. Sûre ne modifie que les fenêtres et les exécutions propres de FileDO. Lit vos données place dans une réponse le contenu de l’écran, le presse-papiers, ou le contenu et les noms de fichiers. Écrit vos données crée, modifie ou supprime vos fichiers ou réglages, ou agit dans un autre programme. Quitte la machine envoie quoi que ce soit hors de cet ordinateur.

Les dix commandes ci-dessus, filedo_win.exe open et filedo_win.exe selftest run sont sûres, donc un FileDO en cours les accepte (ou ouvre le conteneur dans son propre processus) sans aucun réglage. Les quatre outils de développement qui écrivent dans un dossier que vous nommez sont dans la classe écrit vos données : ils s’exécutent dans leur propre processus quand vous les lancez vous-même, et aucun autre programme ne peut les atteindre par la fenêtre en cours d’exécution.

Le seul réglage

Une commande de toute classe autre que sûre est refusée avec le code 12 tant que vous n’activez pas, dans Réglages, groupe Windows et position des fenêtres, l’option Permettre à d’autres programmes de demander à FileDO de travailler avec mes fichiers, l’écran, le presse-papiers ou le réseau. Elle est désactivée tant que vous ne l’activez pas, vous seul pouvez l’activer, et aucune commande ne la modifie. filedo status indique si elle est activée.

Même utilisateur, jamais le réseau

Les commandes passent par un canal local que seul votre propre compte Windows, dans votre propre session, peut atteindre. Rien ne passe par le réseau, et un FileDO lancé en administrateur ne répond qu’aux appelants eux aussi lancés en administrateur (code 12).

Où un script ou un agent trouve la liste

filedo commands --json affiche tout le manifeste - chaque commande avec ses options, sa réponse, son risque, ses codes de sortie et ses exemples - depuis la copie installée, sans fenêtre. La même liste est écrite dans docs/CLI.md.

Pour savoir ce que FileDO fait avant d’agir, préférez filedo status, filedo job list et filedo vd status json à une capture d’écran. Les autres verbes de FileDO - filedo E: info, filedo copy, filedo vd mount et tout ce qu’affiche filedo -? - sont des programmes distincts, avec leurs propres classes de sortie ; le démarrage rapide les liste.
