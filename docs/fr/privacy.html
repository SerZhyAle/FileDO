Politique de confidentialité

FileDO fonctionne uniquement sur votre ordinateur

FileDO n’envoie rien nulle part. Il ne se connecte jamais à Internet et n’a ni télémétrie, ni statistiques d’usage, ni publicité, ni compte, ni vérification des mises à jour. Tout ce qu’il lit et écrit reste sur votre propre disque.

Aucun réseau Aucune télémétrie Aucun compte Open source
Date d’entrée en vigueur : 2026-07-30 S’applique à : FileDO CLI et FileDO GUI pour Windows - dans tous les canaux de distribution (GitHub, winget, Microsoft Store)

01 En bref

Nous ne collectons rien

L’auteur n’exploite aucun serveur, ne tient aucune base de données et n’a aucun moyen de savoir ce que vous faites dans l’application. Aucune donnée personnelle n’est collectée, conservée ni partagée - ni avec nous, ni avec personne d’autre.

L’application ne se connecte jamais

FileDO ne se connecte ni à Internet ni à aucun autre ordinateur. L’unique socket qu’il ouvre sert un disque virtuel .fdd monté à l’initiateur iSCSI de Windows lui-même et n’écoute que sur 127.0.0.1 : rien ne quitte cet ordinateur, et le conteneur ne passe jamais par un réseau. Le paquet du Microsoft Store ne déclare aucune capacité Internet, si bien que Windows n’en accorderait de toute façon aucune.

Un disque que vous choisissez de partager

Si vous installez Fast Media Sorter pour Windows et partagez un disque avec lui (vd share), c’est ce programme - et non FileDO - qui sert les fichiers du disque ouvert sur le réseau aux appareils que vous avez associés. FileDO lui-même n’ouvre aucune connexion réseau pour cela : il dialogue avec ce programme par un canal nommé local sur cet ordinateur, et le partage est désactivé tant que vous ne l’activez pas, disque par disque. Tant qu’un disque partagé est ouvert, chaque appareil associé peut lire ses fichiers, même si le conteneur est chiffré ; fermer le disque ou arrêter l’ordinateur y met fin. Un disque chiffré n’est déverrouillé que sur cet ordinateur, jamais depuis le téléphone. Si vous activez le démarrage automatique d’un disque partagé chiffré, son mot de passe est conservé sur cet ordinateur, protégé pour ce programme, afin que le disque se rouvre après un redémarrage sans que personne le saisisse ; il est supprimé quand vous désactivez le démarrage automatique, arrêtez le partage ou changez le mot de passe. FileDO écrit la liste des disques partagés (chemin, nom, indicateur de démarrage automatique - jamais un mot de passe) dans son dossier d’état. Pour l’activer, le désactiver et reprendre après une étape ayant échoué, consultez le guide partage via Fast Media Sorter & Sharing.

Vous pouvez le vérifier vous-même

FileDO est distribué en open source sous licence MIT. Chaque promesse de cette page peut se vérifier en lisant le code, sans qu’il faille nous croire sur parole.

02 Ce que FileDO lit sur votre machine

Uniquement ce que vous lui désignez par une commande, et seulement pendant l’exécution de cette commande :

  • Les fichiers et dossiers que vous avez nommés. Leur contenu est lu pour mesurer la vitesse, détecter la corruption, comparer des arborescences et calculer des empreintes SHA-256 lors de la recherche de doublons. FileDO ne parcourt jamais votre disque de lui-même et n’ouvre rien en dehors du chemin que vous lui avez donné.
  • Les caractéristiques techniques du disque. Pour la commande info, FileDO demande à Windows, via WMI, le modèle, le numéro de série et le type d’interface du disque physique, ainsi que sa taille et son espace libre. Ces informations s’affichent à l’écran pour que vous voyiez avec quel périphérique vous travaillez. Elles ne sont pas écrites dans le journal des opérations et ne sont envoyées nulle part.
  • « Réseau » désigne ici un partage SMB, pas Internet. Quand FileDO travaille avec un chemin comme \\server\share, il le traite comme un chemin de système de fichiers ordinaire par l’intermédiaire de Windows. L’application n’ouvre aucune connexion de son propre chef vers un autre ordinateur.

03 Ce que FileDO écrit - et où

Des fichiers de service, plus des données de test quand vous les demandez. Ce sont tous des fichiers ordinaires sur votre propre disque : vous pouvez les lire, les supprimer ou ne jamais les créer.

Fichier Où il se trouve Ce qu’il contient
history.json Dans votre propre dossier FileDO, %LOCALAPPDATA%\FileDO\state\, quel que soit l’endroit d’où la commande a été lancée. Dans la version du Microsoft Store, Windows garde ce dossier dans le stockage par utilisateur propre au paquet, sous %LOCALAPPDATA%\Packages\. Un fichier laissé par une version antérieure dans le répertoire courant est copié ici une fois, puis laissé où il était. Afficher l’aide ou l’historique n’écrit rien. Un journal des opérations : l’heure, le nom de la commande, le chemin auquel vous l’avez appliquée, la ligne de commande complète, les paramètres, les résultats (vitesse, nombre de fichiers), la durée et le texte de l’erreur s’il y en a eu une. Les 1000 dernières entrées sont conservées ; les plus anciennes disparaissent. Un mot de passe n’atteint jamais ce fichier - il est masqué avant l’écriture de la ligne - pas plus que le vrai nom scellé dans un conteneur .fd-sec : l’ouverture d’un conteneur enregistre le dossier où la copie est allée, et rien sur le nom du fichier.
hash_cache.json Dans le même dossier FileDO, %LOCALAPPDATA%\FileDO\state\ (dans la version du Microsoft Store, dans le stockage par utilisateur propre au paquet). Un cache qu’une version antérieure gardait à côté de l’exécutable est copié ici une fois. Un cache qui accélère une nouvelle recherche de doublons : chemin du fichier, taille, date de modification, identifiant du fichier sur son volume et empreintes SHA-256 calculées. Aucun contenu de fichier n’y est stocké.
skip_files.list, check_damaged.list, check_files.list Dans le même dossier FileDO, %LOCALAPPDATA%\FileDO\state\ - jamais dans le dossier d’où une commande a été lancée. Une liste laissée là par une version antérieure est copiée une fois, puis laissée où elle était. Chemins de fichiers, tailles et dates de modification, numéro de série du volume et identifiant du fichier sur ce volume (une entrée ne vaut donc que pour le support sur lequel elle a été enregistrée) : les fichiers qu’une copie saute parce qu’ils sont endommagés, les fichiers qu’un contrôle a trouvés endommagés et les fichiers qu’un contrôle a déjà lus sans erreur (pour --resume). Aucun contenu de fichier.
Fichiers de test Dans la cible que vous avez donnée aux commandes speed, test ou fill. Des données générées pour mesurer la vitesse et vérifier la capacité réelle. Supprimées par la commande clean.
Une copie ouverte sans extraction et une copie « Unsecure and start » Dans %LOCALAPPDATA%\FileDO\reveal\, dans son propre répertoire au nom aléatoire. Sa liste d’accès ne nomme que ce compte et le système, et la copie elle-même est en lecture seule. La copie qu’écrit unsecure start - le double-clic sur un conteneur - se trouve dans le même dossier sous la même liste d’accès, mais reste un fichier ordinaire : c’est votre propre fichier, simplement déballé. Le contenu du conteneur .fd-sec que vous avez ouvert, en clair, tant qu’il reste ouvert. La copie disparaît quand vous le demandez ou quand le programme qui l’a ouverte la relâche ; après une coupure de courant, elle reste jusqu’au prochain démarrage de FileDO, qui la balaie. Une copie unsecure start disparaît à la fermeture de la fenêtre de console ou - si le programme l’a alors encore ouverte - au prochain démarrage de FileDO. Rien n’en quitte la machine.
%LOCALAPPDATA%\FileDO\runs Dans %LOCALAPPDATA%\FileDO\runs\. Des fichiers temporaires de flux d’événements pour suivre les opérations en cours dans l’interface graphique. Conservés 7 jours, balayés au démarrage.
%LOCALAPPDATA%\FileDO\reports Dans %LOCALAPPDATA%\FileDO\reports\. Des rapports JSON structurés des opérations terminées et de leurs verdicts. Conservés 30 jours, balayés au démarrage.
vdisk-state.json, vdisk.log Dans %LOCALAPPDATA%\FileDO\state\. Disques virtuels (.fdd) : les noms courts que vous avez donnés aux conteneurs (vd add), leurs chemins, ce qui est monté en ce moment et un journal des montages et démontages ; tant qu’un disque est monté, ses fichiers de travail se trouvent à côté. Le mot de passe d’un conteneur n’est jamais écrit ici. Le serveur de blocs d’un disque monté n’écoute que sur 127.0.0.1 : le contenu des fichiers ne circule sur le réseau que si vous activez séparément le partage via Fast Media Sorter & Sharing.
vdisk-shared.json Dans %LOCALAPPDATA%\FileDO\state\. Les disques que vous avez partagés avec Fast Media Sorter pour Windows : le chemin du conteneur, le nom de dossier sous lequel il est partagé, les indicateurs lecture seule et démarrage automatique. Un mot de passe n’est jamais écrit ici.
Désactiver le journal

Ajoutez nohist (ou no_history) à la commande et l’exécution n’est pas du tout enregistrée dans history.json. Si le fichier ne peut pas être écrit, FileDO ne tient simplement pas de journal et continue. Vous pouvez supprimer le fichier à tout moment.

04 Si vous choisissez d’envoyer les logs à l’auteur

La fenêtre À propos contient un bouton Envoyer les logs à l’auteur. C’est le seul endroit du programme d’où des données peuvent quitter votre machine - et uniquement de votre propre main. Il ne se déclenche jamais automatiquement, ni sur minuterie, ni en cas d’échec.

  • Ce qui est collecté. Les journaux texte et rapports FileDO nettoyés, pris dans le dossier du programme et dans %LOCALAPPDATA%\FileDO, y compris son dossier state. L’historique des opérations, les rapports JSON et les listes de fichiers sont exclus. environment.txt contient des informations sur la version, Windows, la langue et le nombre de journaux ; filedo-report.txt liste des noms d’entrées d’archive neutres. Les archives de plus de sept jours sont supprimées à l’export suivant.
  • Nettoyage avant l’archivage. Les lignes contenant des identifiants, des URL et des chemins absolus deviennent [REDACTED] ; les blocs de clés privées sont entièrement retirés. Les journaux d’origine sur le disque restent inchangés. Un texte libre peut contenir des données personnelles : relisez l’archive avant de l’envoyer.
  • Vous voyez d’abord l’archive. Le zip est écrit dans %TEMP%\FileDO_Logs\, le dossier s’ouvre avec le fichier sélectionné et le chemin complet est placé dans votre presse-papiers. Ouvrez-le, retirez ce que vous préférez ne pas partager, ou supprimez-le simplement - et tout s’arrête là.
  • C’est vous qui envoyez, pas le programme. FileDO ouvre votre propre programme de messagerie avec l’adresse de l’auteur, un objet et un brouillon de message. Vous joignez vous-même l’archive et vous envoyez vous-même le message, depuis votre propre compte. FileDO n’a ni serveur, ni envoi de courrier de sa part, ni requête réseau - ici comme partout ailleurs.
  • Ce qu’il advient de ce que vous envoyez. Le message arrive dans la boîte aux lettres personnelle de l’auteur et sert uniquement à résoudre votre problème. Il n’entre dans aucune base de données, aucun outil d’analyse et aucune main tierce.

05 Autorisations, destruction de données et programmes externes

  • FileDO n’élève jamais ses droits en silence. Il s’exécute avec les droits que vous avez déjà. Deux tâches de réparation de disque dans la fenêtre demandent à Windows les droits d’administrateur pour cette seule exécution, et vous voyez l’invite. Les opérations en terminal qui exigent des droits élevés sont lancées en administrateur par vous, délibérément.
  • Accès de bureau en confiance totale (runFullTrust). La version du Microsoft Store déclare cette unique capacité, car lire et écrire directement sur le disque est précisément ce que sont les tests de vitesse et de capacité. Le paquet ne déclare aucune autre capacité - accès Internet compris.
  • Les commandes wipe et fill détruisent des données - c’est leur rôle. Elles demandent toujours confirmation et ne s’exécutent jamais en silence sur la racine d’un lecteur, un point d’analyse (jonction, lien symbolique) ou le dossier TEMP du système. Les écritures visant C: sont par défaut redirigées vers %TEMP%\FileDO_Operations - là encore, seulement après votre confirmation.
  • FileDO lance parfois des programmes Windows intégrés. Lors de la récupération d’un disque (probe), il peut appeler chkdsk, format ou Format-Volume de PowerShell sur le disque que vous avez nommé. Et si vous donnez à la commande from un fichier listant des commandes, FileDO exécute ces lignes - y compris celles qui démarrent d’autres programmes. Ce qui s’exécute est exactement ce que vous avez écrit. Dans la fenêtre À propos, les liens s’ouvrent dans votre navigateur, et le bouton d’envoi des logs ouvre l’Explorateur et votre programme de messagerie - seulement une fois que vous l’avez pressé.

06 Ce site web

Tout ce qui précède décrit l’application. Le site web est une autre affaire, et il est juste de le nommer aussi. Le site ne pose aucun outil d’analyse, n’affiche aucune publicité et n’utilise aucun cookie, mais l’ouverture d’une page fait bien contacter trois adresses extérieures par votre navigateur :

  • GitHub Pages - le site y est hébergé. GitHub, comme tout hébergeur web, voit les requêtes pour ces pages ; cela relève de la déclaration de confidentialité propre à GitHub.
  • Google Fonts - la page charge ses polices depuis fonts.googleapis.com et fonts.gstatic.com.
  • API GitHub - la page d’accueil interroge api.github.com pour connaître la dernière version, afin que le bouton de téléchargement pointe vers la version actuelle.

Comme pour toute requête sur Internet, ces services voient votre adresse IP et les informations de votre navigateur. Vos choix de langue et de thème sont stockés localement dans votre navigateur et ne sont jamais envoyés nulle part. L’application installée ne fait rien de tout cela.

07 Enfants, modifications et contact

FileDO est un outil de stockage. Il ne s’adresse pas aux enfants et ne collecte aucune donnée sur personne, enfants compris.

Si cette politique change, la nouvelle version paraît sur cette même page avec une nouvelle date d’entrée en vigueur. L’historique complet des modifications est public dans le dépôt.
