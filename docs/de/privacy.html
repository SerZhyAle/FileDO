Datenschutzerklärung

FileDO läuft nur auf Ihrem Computer

FileDO sendet nirgendwohin etwas. Es verbindet sich nie mit dem Internet und hat keine Telemetrie, keine Analytik, keine Werbung, keine Konten und keine Update-Prüfung. Alles, was es liest und schreibt, bleibt auf Ihrem eigenen Datenträger.

Kein Netzwerk Keine Telemetrie Keine Konten Open Source
Gültig ab: 2026-07-30 Gilt für: FileDO CLI und FileDO GUI für Windows - in jedem Vertriebskanal (GitHub, winget, Microsoft Store)

01 Kurz gesagt

Wir erheben nichts

Der Autor betreibt keine Server, führt keine Datenbank und hat keine Möglichkeit zu erfahren, was Sie in der App tun. Es werden keine personenbezogenen Daten erhoben, gespeichert oder weitergegeben - weder an uns noch an sonst jemanden.

Die App geht nie online

FileDO verbindet sich weder mit dem Internet noch mit einem anderen Computer. Der einzige Socket, den es öffnet, stellt einen eingebundenen virtuellen .fdd-Datenträger dem iSCSI-Initiator von Windows selbst bereit und lauscht ausschließlich auf 127.0.0.1: Nichts verlässt diesen Computer, und der Container gelangt in kein Netzwerk. Das Microsoft-Store-Paket deklariert keine Internetfunktion, daher würde Windows ohnehin keine gewähren.

Ein Datenträger, den Sie freigeben

Wenn Sie Fast Media Sorter for Windows installieren und einen Datenträger damit freigeben (vd share), stellt dieses Programm - nicht FileDO - die Dateien des geöffneten Datenträgers über das Netzwerk den Geräten bereit, die Sie mit ihm gekoppelt haben. FileDO selbst öffnet dafür keine Netzwerkverbindung: Es spricht mit diesem Programm über eine lokale Pipe auf diesem Computer, und die Freigabe ist ausgeschaltet, bis Sie sie einschalten, Datenträger für Datenträger. Solange ein freigegebener Datenträger geöffnet ist, kann jedes gekoppelte Gerät seine Dateien lesen, auch wenn der Container verschlüsselt ist; das Schließen des Datenträgers oder das Ausschalten des Computers beendet das. Ein verschlüsselter Datenträger wird nur auf diesem Computer entsperrt, nie vom Smartphone aus. Wenn Sie den Autostart für einen verschlüsselten freigegebenen Datenträger einschalten, wird sein Passwort auf diesem Computer aufbewahrt, für dieses Programm geschützt, damit sich der Datenträger nach einem Neustart wieder öffnet, ohne dass jemand es eintippt; es wird entfernt, wenn Sie den Autostart ausschalten, die Freigabe beenden oder das Passwort ändern. FileDO schreibt die Liste der freigegebenen Datenträger (Pfad, Name, Autostart-Markierung - nie ein Passwort) in seinen Statusordner. Wie Sie die Freigabe ein- und ausschalten und sich nach einem fehlgeschlagenen Schritt erholen, steht in der Anleitung Freigabe über Fast Media Sorter & Sharing.

Sie können das selbst überprüfen

FileDO wird als Open Source unter der MIT-Lizenz ausgeliefert. Jedes Versprechen auf dieser Seite lässt sich durch Lesen des Codes prüfen, statt uns zu vertrauen.

02 Was FileDO auf Ihrem Rechner liest

Nur das, worauf Sie es mit einem Befehl richten, und nur solange dieser Befehl läuft:

  • Die Dateien und Ordner, die Sie angegeben haben. Ihr Inhalt wird gelesen, um die Geschwindigkeit zu messen, auf Beschädigungen zu prüfen, Verzeichnisbäume zu vergleichen und bei der Suche nach Duplikaten SHA-256-Hashes zu berechnen. FileDO durchsucht Ihren Datenträger nie von sich aus und öffnet nichts außerhalb des Pfads, den Sie angegeben haben.
  • Technische Angaben zum Laufwerk. Für den Befehl info fragt FileDO Windows über WMI nach Modell, Seriennummer und Schnittstellentyp des physischen Datenträgers sowie nach Größe und freiem Speicher. Sie werden auf dem Bildschirm ausgegeben, damit Sie sehen, mit welchem Gerät Sie arbeiten. Sie werden nicht in das Vorgangsprotokoll geschrieben und nirgendwohin gesendet.
  • „Netzwerk“ meint hier eine SMB-Freigabe, nicht das Internet. Wenn FileDO mit einem Pfad wie \\server\share arbeitet, behandelt es ihn über Windows wie einen gewöhnlichen Dateisystempfad. Die App öffnet keine eigene Verbindung zu einem anderen Computer.

03 Was FileDO schreibt - und wohin

Verwaltungsdateien, dazu Testdaten, wenn Sie danach fragen. Alle sind gewöhnliche Dateien auf Ihrem eigenen Datenträger: Sie können sie lesen, löschen oder gar nicht erst anlegen lassen.

Datei Wo sie landet Was darin steht
history.json In Ihrem eigenen FileDO-Ordner %LOCALAPPDATA%\FileDO\state\, egal wo der Befehl gestartet wurde. In der Microsoft-Store-Version legt Windows diesen Ordner im eigenen Benutzerspeicher des Pakets unter %LOCALAPPDATA%\Packages\ ab. Eine Datei, die eine frühere Version im aktuellen Verzeichnis hinterlassen hat, wird einmal dorthin kopiert und bleibt, wo sie war. Hilfe oder Verlauf anzuzeigen schreibt nichts. Ein Vorgangsprotokoll: Zeit, Befehlsname, der Pfad, auf den Sie ihn angewendet haben, die vollständige Befehlszeile, Parameter, Ergebnisse (Geschwindigkeit, Dateianzahlen), Dauer und gegebenenfalls der Fehlertext. Die letzten 1000 Einträge werden aufbewahrt; ältere fallen heraus. Ein Passwort gelangt nie in diese Datei - es wird geschwärzt, bevor die Zeile geschrieben wird - und der versiegelte echte Name in einem .fd-sec-Container ebenso wenig: Beim Öffnen wird der Ordner vermerkt, in den die Kopie ging, aber nichts darüber, wie die Datei hieß.
hash_cache.json Im selben FileDO-Ordner %LOCALAPPDATA%\FileDO\state\ (in der Microsoft-Store-Version im eigenen Benutzerspeicher des Pakets). Ein Cache, den eine frühere Version neben der ausführbaren Datei angelegt hat, wird einmal dorthin kopiert. Ein Cache, der einen wiederholten Duplikat-Scan beschleunigt: Dateipfad, Größe, Änderungszeit, die ID der Datei auf ihrem Volume und die berechneten SHA-256-Hashes. Dateiinhalte werden darin nicht gespeichert.
skip_files.list, check_damaged.list, check_files.list Im selben FileDO-Ordner %LOCALAPPDATA%\FileDO\state\ - nie in dem Ordner, aus dem ein Befehl gestartet wurde. Eine Liste, die eine frühere Version dort hinterlassen hat, wird einmal kopiert und bleibt, wo sie war. Dateipfade, Größen und Änderungszeiten, die Seriennummer des Volumes und die ID der Datei auf diesem Volume (damit ein Eintrag nur für das Medium gilt, auf dem er aufgezeichnet wurde): die Dateien, die ein Kopiervorgang als beschädigt überspringt, die Dateien, die eine Prüfung als beschädigt gefunden hat, und die Dateien, die eine Prüfung bereits fehlerfrei gelesen hat (für --resume). Keine Dateiinhalte.
Testdateien In dem Ziel, das Sie den Befehlen speed, test oder fill angegeben haben. Erzeugte Daten, mit denen Geschwindigkeit gemessen und die tatsächliche Kapazität geprüft wird. Werden mit dem Befehl clean entfernt.
Eine Reveal-Kopie und eine Kopie von „Unsecure and start“ In %LOCALAPPDATA%\FileDO\reveal\, in einem eigenen Verzeichnis mit zufälligem Namen. Seine Zugriffsliste nennt nur dieses Konto und das System, und die Kopie selbst ist schreibgeschützt. Die Kopie, die unsecure start schreibt - der Doppelklick auf einen Container -, liegt im selben Ordner unter derselben Zugriffsliste, bleibt aber eine gewöhnliche Datei: Es ist Ihre eigene Datei, nur ausgepackt. Der Inhalt des .fd-sec-Containers, den Sie geöffnet haben, im Klartext, solange er geöffnet ist. Die Kopie verschwindet, wenn Sie es sagen oder wenn das Programm, das sie geöffnet hat, sie loslässt; nach einem Stromausfall bleibt sie bis zum nächsten FileDO-Start, der sie aufräumt. Eine Kopie von unsecure start verschwindet, wenn das Konsolenfenster geschlossen wird, oder - falls das Programm sie dann noch geöffnet hat - beim nächsten FileDO-Start. Nichts davon verlässt den Rechner.
%LOCALAPPDATA%\FileDO\runs In %LOCALAPPDATA%\FileDO\runs\. Temporäre Ereignisstrom-Dateien zur Verfolgung aktiver Vorgänge in der GUI. Werden 7 Tage aufbewahrt und beim Start aufgeräumt.
%LOCALAPPDATA%\FileDO\reports In %LOCALAPPDATA%\FileDO\reports\. Strukturierte JSON-Laufberichte abgeschlossener Vorgänge und Ergebnisse. Werden 30 Tage aufbewahrt und beim Start aufgeräumt.
vdisk-state.json, vdisk.log In %LOCALAPPDATA%\FileDO\state\. Virtuelle Datenträger (.fdd): die kurzen Namen, die Sie Containern gegeben haben (vd add), ihre Pfade, was gerade eingebunden ist, und ein Protokoll der Einbindungen und Trennungen; solange ein Datenträger eingebunden ist, liegen seine Arbeitsdateien daneben. Das Passwort eines Containers wird hier nie geschrieben. Der Blockserver eines eingebundenen Datenträgers lauscht ausschließlich auf 127.0.0.1: Dateiinhalte werden nur dann über das Netzwerk bereitgestellt, wenn Sie die Freigabe über Fast Media Sorter & Sharing ausdrücklich separat aktivieren.
vdisk-shared.json In %LOCALAPPDATA%\FileDO\state\. Datenträger, die Sie mit Fast Media Sorter for Windows freigegeben haben: der Pfad des Containers, der Ordnername, unter dem er freigegeben ist, die Markierungen für schreibgeschützt und Autostart. Ein Passwort wird hier nie geschrieben.
Das Protokoll ausschalten

Fügen Sie dem Befehl nohist (oder no_history) hinzu, und der Lauf wird überhaupt nicht in history.json aufgezeichnet. Lässt sich die Datei nicht schreiben, führt FileDO einfach kein Protokoll und arbeitet weiter. Sie können die Datei jederzeit löschen.

04 Wenn Sie die Logs an den Autor senden

Das Fenster „Über“ enthält die Schaltfläche „Logs an den Autor senden“. Sie ist die einzige Stelle im Programm, von der aus Daten Ihren Rechner verlassen können - und nur durch Ihre eigene Hand. Sie löst nie automatisch aus, nicht nach einem Zeitplan und nicht bei einem Fehler.

  • Was erfasst wird. Bereinigte FileDO-Textlogs und -Berichte aus dem Programmordner und aus %LOCALAPPDATA%\FileDO, einschließlich seines Ordners state. Betriebsverlauf, JSON-Berichte und Dateilisten sind ausgeschlossen. environment.txt enthält Angaben zu Build, Windows, Sprache und Anzahl der Logs; filedo-report.txt listet neutrale Namen der Archiveinträge. Archive, die älter als sieben Tage sind, werden beim nächsten Export entfernt.
  • Bereinigung vor dem Packen. Zeilen mit Zugangsdaten, URLs und absoluten Pfaden werden zu [REDACTED]; Blöcke mit privaten Schlüsseln werden vollständig entfernt. Die Original-Logs auf dem Datenträger bleiben unverändert. Freitext kann persönliche Angaben enthalten, prüfen Sie das Archiv daher, bevor Sie es senden.
  • Sie sehen zuerst das Archiv. Das Zip wird nach %TEMP%\FileDO_Logs\ geschrieben, der Ordner öffnet sich mit der markierten Datei, und der vollständige Pfad landet in Ihrer Zwischenablage. Öffnen Sie es, entfernen Sie alles, was Sie lieber nicht teilen möchten, oder löschen Sie es einfach - dann ist die Sache erledigt.
  • Sie senden es, nicht das Programm. FileDO öffnet Ihr eigenes Mailprogramm mit der Adresse des Autors, einem Betreff und einem Entwurfstext. Sie hängen das Archiv selbst an und senden die Mail selbst, von Ihrem eigenen Konto. FileDO hat keinen Server, kein eigenes Mailsenden und keine Netzwerkanfragen - hier wie überall sonst.
  • Was mit dem geschieht, was Sie senden. Die Mail kommt im persönlichen Postfach des Autors an und dient nur dazu, Ihr Problem zu klären. Sie landet in keiner Datenbank, keiner Analytik und nicht in den Händen Dritter.

05 Berechtigungen, Datenvernichtung und externe Programme

  • FileDO erhöht nie stillschweigend die Rechte. Es läuft mit den Rechten, die Sie ohnehin haben. Zwei Laufwerk-Reparaturaufgaben im Fenster fragen Windows für diesen einen Lauf nach Administratorrechten, und Sie sehen die Abfrage. Terminal-Vorgänge, die erhöhte Rechte erfordern, starten Sie bewusst selbst als Administrator.
  • Vollvertrauenswürdiger Desktop-Zugriff (runFullTrust). Die Microsoft-Store-Version deklariert genau diese eine Funktion, denn das Lesen und Schreiben des Laufwerks direkt ist das, was Geschwindigkeits- und Kapazitätstests ausmacht. Das Paket deklariert keine weitere Funktion - auch keinen Internetzugriff.
  • Die Befehle wipe und fill vernichten Daten - das ist ihre Aufgabe. Sie fragen immer nach einer Bestätigung und laufen nie stillschweigend gegen ein Laufwerks-Stammverzeichnis, einen Reparsepunkt (Junction, Symlink) oder den TEMP-Ordner des Systems. Schreibvorgänge, die auf C: zielen, werden standardmäßig nach %TEMP%\FileDO_Operations umgeleitet - auch das erst nach Ihrer Bestätigung.
  • FileDO startet manchmal integrierte Windows-Programme. Bei der Wiederherstellung eines Laufwerks (probe) kann es chkdsk, format oder das Format-Volume von PowerShell gegen das von Ihnen genannte Laufwerk aufrufen. Und wenn Sie dem Befehl from eine Datei mit einer Liste von Befehlen übergeben, führt FileDO diese Zeilen aus - auch Zeilen, die andere Programme starten. Ausgeführt wird genau das, was Sie geschrieben haben. Im Fenster „Über“ öffnen sich die Links in Ihrem Browser, und die Schaltfläche zum Senden der Logs öffnet den Explorer und Ihr Mailprogramm - erst, wenn Sie sie gedrückt haben.

06 Diese Website

Alles oben Gesagte beschreibt die App. Die Website ist eine andere Sache, und es ist nur fair, auch sie zu nennen. Die Website setzt keine Analytik, zeigt keine Werbung und verwendet keine Cookies, doch beim Öffnen einer Seite erreicht Ihr Browser drei externe Adressen:

  • GitHub Pages - die Website wird dort gehostet. GitHub sieht, wie jeder Webhoster, die Anfragen nach diesen Seiten; das richtet sich nach der eigenen Datenschutzerklärung von GitHub.
  • Google Fonts - die Seite lädt ihre Schriften von fonts.googleapis.com und fonts.gstatic.com.
  • GitHub API - die Startseite fragt bei api.github.com nach dem neuesten Release, damit die Download-Schaltfläche auf die aktuelle Version zeigt.

Wie bei jeder Anfrage im Internet sehen diese Dienste Ihre IP-Adresse und Browserdetails. Ihre Sprach- und Designauswahl wird lokal in Ihrem Browser gespeichert und nirgendwohin gesendet. Die installierte App tut nichts davon.

07 Kinder, Änderungen und Kontakt

FileDO ist ein Speicher-Werkzeug. Es richtet sich nicht an Kinder und erhebt keine Daten über irgendjemanden, Kinder eingeschlossen.

Wenn sich diese Erklärung ändert, erscheint die neue Fassung auf derselben Seite mit einem neuen Gültigkeitsdatum. Der vollständige Änderungsverlauf ist im Repository öffentlich.
