Anleitung · geheime Dateien

Eine Datei oder ein Ordner, ein Container, ein Passwort - und eine ehrliche Auskunft, was das bringt.

FileDO packt eine Datei - oder einen ganzen Ordner - in einen .fd-sec-Container, holt sie wieder heraus und kann den Inhalt im zugehörigen Programm öffnen, ohne ihn auszupacken. Der wahre Name, die Größe und die Zeitstempel sind darin versiegelt; von außen sind nur die eigene Größe des Containers, sein sichtbarer Name und seine Zeitstempel zu sehen (Umbenennen erzeugt einen namenlosen Datenblock).

Drei Vorgänge

Alles Weitere ist Detail zu diesen dreien. Jeder ist von der Befehlszeile aus verfügbar, aus der Gruppe „File DO..“ im Explorer-Kontextmenü und auf den Seiten der Gruppe „Schützen“ im Programmfenster.

Einpacken

Neben der Datei erscheint eine report.fd-sec. Das Passwort wird zweimal abgefragt und nie angezeigt. Das Original bleibt, wo es ist, bis Sie verlangen, dass es verschwindet.

filedo report.docx secure

Eine Datei zurückholen (unsecure)

Die Datei kommt unter ihrem versiegelten Namen und mit ihren eigenen Zeitstempeln zurück. Eine vorhandene Datei wird nie stillschweigend überschrieben.

filedo report.fd-sec unsecure

Öffnen ohne Auspacken

Der Inhalt öffnet sich im zugehörigen Programm, aus einer temporären Kopie, die danach wieder entfernt wird. Dieser Befehl wird von Hand eingegeben; ein Doppelklick auf den Container tut etwas anderes - siehe unten.

filedo report.fd-sec reveal
Auch ein Ordner ist eine Datei

secure nimmt auch einen Ordner: Sein ganzer Baum, leere Unterordner eingeschlossen, kommt in einen einzigen .fd-sec, der von außen nicht von einem Datei-Container zu unterscheiden ist. unsecure stellt den Baum zuerst in einem temporären Ordner wieder her und verschiebt ihn erst an seinen Platz, nachdem jede Datei geprüft ist - nie in oder über einen vorhandenen Ordner. Ein Ordner mit einer Junction, einer symbolischen Verknüpfung oder einem Bereitstellungspunkt wird abgelehnt. del und wipe entfernen den Originalbaum nur, wenn er sich seit dem Einpacken nicht geändert hat. reveal öffnet eine einzelne Datei und nimmt keinen Ordner-Container.

filedo "Tax 2025" secure
Die leise Suite: suite2

secure suite2 versiegelt eine Datei (keinen Ordner) mit Suite 2 statt der Standard-Suite 1: ein mit Pepper gefalteter Argon2id-Schlüssel mit 256 MiB und XChaCha20-Poly1305 in 64-KiB-Frames, sodass die Datei ab dem ersten Byte Rauschen ist, ohne auch nur das 512-Byte-Clusterlängenmuster von Suite 1. Der wahre Name, die tatsächliche Größe und der Zeitpunkt der Verschlüsselung bleiben erhalten, nicht aber die eigenen Zeitstempel des Originals: Die wiederhergestellte Datei erhält die aktuelle Zeit. Nur FileDO ab dieser Version öffnet sie - ältere FileDO-Builds melden sie als beschädigt oder als falsches Passwort, und FastMediaSorter-Apps können sie nicht öffnen, deshalb bleibt Suite 1 der Standard. unsecure, reveal, fdsec info und fdsec verify erkennen die Suite selbst; sonst ändert sich nichts, und ein leeres Passwort bleibt reine Verschleierung.

filedo report.docx secure suite2

Was versprochen wird und was nicht

Ein leeres Passwort

Ein leeres Passwort wird angenommen, und es bedeutet nur Verschleierung - keine Geheimhaltung: Jeder, der das Format kennt, öffnet diese Datei. Ein kurzes Passwort ist kaum besser. Es gibt keinen Wiederherstellungsschlüssel: Ein vergessenes Passwort ist eine verlorene Datei.

Das Original überschreiben

secure del entfernt das Original so, dass jedes Undelete-Werkzeug es zurückholen kann. secure wipe überschreibt es zuvor - das senkt die Chancen auf Wiederherstellung und verspricht nichts auf SSDs sowie auf Copy-on-Write- und journalisierenden Dateisystemen, wo das Überschreiben an Ort und Stelle nicht garantiert, dass die alten Blöcke weg sind. Standardmäßig bleibt das Original einfach erhalten.

Wo eine geöffnete Kopie liegt

In %LOCALAPPDATA%\FileDO\reveal, schreibgeschützt und nur für dieses Konto lesbar. Die Kopie verschwindet, wenn Sie es sagen - mit der Schaltfläche „Kopie jetzt entfernen“ im Fenster oder mit Enter in der Konsole - oder wenn das Programm, das sie geöffnet hat, sie freigibt. Fällt der Strom aus, bleibt die Kopie bis zum nächsten FileDO-Start, der sie aufräumt; sonst tut es nichts. Programmdateien und Skripte werden nie aus einem Container heraus gestartet: Sie werden extrahiert und ihr Speicherort wird angezeigt.

Das Passwort und das Protokoll

Im Fenster ist das Passwort maskiert und wird unsichtbar an filedo.exe übergeben: Es steht in keiner Befehlszeile, in keinem Laufbericht und in keiner history.json. In der Befehlszeile ist die Form p:password in der Prozessliste sichtbar - für Skripte gibt es pf: (eine Datei), pe: (eine Umgebungsvariable) und k: (eine Schlüsseldatei). Auch der versiegelte wahre Name wird nie ins Protokoll geschrieben.

Der Doppelklick und das Explorer-Menü

Das Installationsprogramm bietet die Explorer-Integration als abwählbare Komponente an. In den Builds ohne Installationsprogramm - winget, ZIP, go install - schaltet ein Befehl sie ein. Ein Doppelklick auf eine .fd-sec ist genau der Menüeintrag „Unsecure and start“: Eine Konsole öffnet sich und fragt dort nach dem Passwort, die Datei wird unter ihrem wahren Namen in %LOCALAPPDATA%\FileDO\reveal wiederhergestellt, wo nur Sie und das System sie lesen können, und gleich an ihr gewöhnliches Programm übergeben - so wie ein gewöhnlicher Doppelklick auf jede andere Datei. Die Kopie wird entfernt, wenn Sie dieses Konsolenfenster schließen; hat das Programm die Datei dann noch offen, entfernt sie der nächste FileDO-Start. Der Container selbst bleibt an seinem Platz. Unter Windows 11 steht die Gruppe „File DO..“ unter „Weitere Optionen anzeigen“. Die Microsoft-Store-Version hat keine Menüeinträge, beansprucht aber den Typ .fd-sec: Ein Doppelklick öffnet das FileDO-Fenster auf der Seite „Geheime Datei öffnen“ mit bereits gewähltem Container, und dort wird nach dem Passwort gefragt.
