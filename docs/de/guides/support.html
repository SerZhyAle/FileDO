Anleitung · Support

Etwas funktioniert nicht? Sagen Sie dem Autor, was Sie gesehen haben.

FileDO wird von einer einzigen Person entwickelt und betreut. Mit einer Meldung, die die Version, Ihre Schritte und das Ergebnis nennt, kann der Autor arbeiten. Im Folgenden: wohin Sie sie schicken, was hineingehört und was Sie vorher lesen sollten.

1. Wo Sie ein Problem melden

Zwei Wege zum Autor, beide kostenlos, dazu eine Abkürzung aus dem Programm. Wählen Sie danach, was Sie mitteilen möchten.

GitHub issues

Der Ort für Fehler, Fragen und Ideen. Sie brauchen ein kostenloses GitHub-Konto, und ein Issue ist öffentlich: Jeder kann es lesen.

Issue-Tracker öffnen

E-Mail

Für alles, was Sie nicht öffentlich posten möchten, oder wenn Sie GitHub nicht nutzen. Schreiben Sie an sza@ukr.net und nennen Sie im Betreff FileDO und die Version.

Aus dem Programm

Die Seite „Über“ des FileDO-Fensters enthält den Link „Ein Problem melden“, die Adresse des Autors und die Schaltfläche „Logs an den Autor senden“ (Abschnitt 3).

2. Was hineingehört

Fünf Angaben machen aus einer Meldung etwas, das der Autor selbst nachstellen kann.

  1. Die FileDO-Version. Öffnen Sie im FileDO-Fenster die Seite „Über“ und lesen Sie die Zeile „GUI-Build“. Führen Sie in einem Terminal filedo --no-ui aus: Oben in der Ausgabe stehen das Datum, die Adresse des Autors und die Version, eine zehnstellige Zahl. Nennen Sie diese Zahl und nicht die aus der Liste der installierten Apps von Windows, die anders geschrieben sein kann.
  2. Wie Sie es installiert haben und welches Windows Sie nutzen. Setup-EXE, MSI, ZIP, winget oder Microsoft Store: Die Builds unterscheiden sich darin, was sie können. Nennen Sie die, die Sie haben, und Ihre Windows-Version (winver zeigt sie an).
  3. Was Sie genau getan haben. Der Befehl, so wie Sie ihn eingegeben haben (die Seite „Befehl“ im Fenster zeigt ihn an und kann ihn kopieren), oder die Seite und die Schaltflächen, die Sie benutzt haben. Lassen Sie jedes Passwort weg.
  4. Was passiert ist und was Sie erwartet haben. Geben Sie Meldungen wörtlich wieder. Nennen Sie den Exit-Code: Nach dem Ende eines Befehls zeigt ihn echo %ERRORLEVEL% in der Eingabeaufforderung oder $LASTEXITCODE in PowerShell. 0 heißt bestanden oder erledigt, 1 heißt Defekt gefunden, 2 heißt nicht prüfbar, und 10 bis 16 nennen den Grund (10 Aufruf falsch, 11 Ziel nicht gefunden oder nicht bereit, 12 Zugriff verweigert, 13 zu wenig Platz, 14 Hardware- oder E/A-Fehler, 15 Netzwerkfehler, 16 gestoppt). Die Container-Befehle (secure, unsecure, reveal, vd) verwenden einen größeren Satz von Codes, der in der README steht.
  5. Logs, wenn möglich. Abschnitt 3 zeigt, wie Sie sie bekommen, ohne nach Dateien zu suchen.

3. Logs, wenn Sie sie senden können

Auf der Seite „Über“ gibt es die Schaltfläche „Logs an den Autor senden“. Sie packt die Text-Logs, die FileDO auf diesem Rechner geschrieben hat, in ein ZIP, öffnet den Ordner mit markiertem ZIP, legt dessen Pfad in die Zwischenablage und öffnet Ihr Mailprogramm mit bereits eingetragener Adresse des Autors. Sie sehen zuerst das ZIP, und nichts wird gesendet, bevor Sie selbst auf Senden drücken.

Ein Mail-Link kann keinen Anhang tragen, deshalb hängen Sie das ZIP selbst an: Sein Pfad liegt bereits in der Zwischenablage.

Lesen Sie das ZIP, bevor Sie es anhängen. In den gepackten Zeilen werden Zugangsdaten, Links und absolute Pfade durch [REDACTED] ersetzt, doch freier Text kann trotzdem persönliche Angaben enthalten. Ein GitHub-Issue ist öffentlich: Hängen Sie das ZIP dort nur an, nachdem Sie es gelesen haben, oder schicken Sie es stattdessen per E-Mail.

Der Verlauf, die Prüflisten und die JSON-Berichte sind nicht im ZIP, weil sie die Namen Ihrer eigenen Dateien und Ordner enthalten können. Die Datenschutzseite listet die Dateien auf, die FileDO schreibt, wo sie liegen und was sie enthalten. Schreiben Sie nie ein Container-Passwort in eine Meldung.

Diese Seiten beantworten Ihre Frage möglicherweise, bevor Sie schreiben.

Einige Funktionen sind in der Microsoft-Store-Version dokumentiert nicht verfügbar: Lesen Sie die Seite zur Microsoft-Store-Version, die Installationsanleitung und den Abschnitt Was Windows liefern muss der Anleitung zu virtuellen Datenträgern, bevor Sie etwas als fehlend melden.

5. Was Sie erwarten können

FileDO hat einen einzigen Betreuer und kein Support-Team. Eine Antwortzeit wird nicht versprochen: Eine Meldung wird gelesen, wenn der Autor dazu kommt, und eine Korrektur, falls es eine gibt, erscheint mit einer späteren Version - was sich geändert hat, zeigen die Versionshinweise. Eine Meldung nach Abschnitt 2 lässt sich leichter bearbeiten.
