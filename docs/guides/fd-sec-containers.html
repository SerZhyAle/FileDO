Guide · secret filesРуководство · секретные файлыПосібник · секретні файли

One file or folder, one container, one password - and a straight account of what that buys.Один файл или папка, один контейнер, один пароль - и честный рассказ о том, что это даёт.Один файл чи тека, один контейнер, один пароль - і чесна розповідь про те, що це дає.

FileDO packs a file - or a whole folder - into a .fd-sec container, brings it back, and can open what is inside in the program it belongs to without unpacking it. The true name, the size and the timestamps are sealed inside; from outside only the container's own size, its visible name and its timestamps are visible (renaming writes a nameless blob).FileDO упаковывает файл - или целую папку - в контейнер .fd-sec, возвращает его обратно и умеет открыть содержимое в нужной программе, не распаковывая. Настоящее имя, размер и отметки времени запечатаны внутри; снаружи видны только размер самого контейнера, его видимое имя и время создания (переименование даёт безымянный блок данных).FileDO пакує файл - або цілу теку - у контейнер .fd-sec, повертає його назад і вміє відкрити вміст у потрібній програмі, не розпаковуючи. Справжнє ім'я, розмір і позначки часу запечатані всередині; ззовні видно лише розмір самого контейнера, його видиме ім'я та позначки часу (перейменування дає безіменний блок даних).

Они доступны из командной строки, из группы «File DO..» в контекстном меню Проводника и со страниц группы «Защита» в окне программы.Усе інше - подробиці цих трьох. Вони доступні з командного рядка, з групи «File DO..» в контекстному меню Провідника та зі сторінок групи «Захист» у вікні програми.

A folder is one file tooПапка - тоже один файлТека - теж один файл

secure takes a folder as well: its whole tree, empty subfolders included, goes into one .fd-sec, which from outside cannot be told from a file's container. unsecure restores the tree into a temporary folder first and moves it into place only after every file has verified - never into or over a folder that exists. A folder holding a junction, a symbolic link or a mount point is refused. del and wipe remove the original tree only if it has not changed since it was packed. reveal opens one file and does not take a folder container.secure принимает и папку: всё её дерево, вместе с пустыми подпапками, уходит в один .fd-sec, и снаружи его не отличить от контейнера файла. unsecure восстанавливает дерево сначала во временную папку и переносит на место только после проверки каждого файла - никогда внутрь или поверх существующей папки. Папка с junction, символической ссылкой или точкой монтирования отклоняется. del и wipe убирают исходное дерево, только если оно не менялось после упаковки. reveal открывает один файл и контейнер папки не принимает.secure приймає й теку: усе її дерево, разом із порожніми підтеками, іде в один .fd-sec, і ззовні його не відрізнити від контейнера файлу. unsecure відновлює дерево спочатку в тимчасову теку й переносить на місце лише після перевірки кожного файлу - ніколи всередину чи поверх наявної теки. Теку з junction, символічним посиланням чи точкою монтування відхилено. del і wipe прибирають вихідне дерево, лише якщо воно не змінювалося після пакування. reveal відкриває один файл і контейнер теки не приймає.

The quiet suite: suite2Тихий набор: suite2Тихий набір: suite2

secure suite2 seals one file (not a folder) with suite 2 instead of the default suite 1: a pepper-folded Argon2id key at 256 MiB and XChaCha20-Poly1305 in 64 KiB frames, so the file is noise from its first byte, without even the 512-byte cluster length pattern suite 1 has. The true name, the real size and the time of encryption are kept, but not the original's own timestamps: the restored file gets the current time. Only FileDO from this version on opens it - older FileDO builds report it as damaged or as a wrong password, and FastMediaSorter apps cannot open it, so suite 1 stays the default. unsecure, reveal, fdsec info and fdsec verify find the suite themselves; nothing else changes, and an empty password is still obfuscation only.secure suite2 запечатывает один файл (не папку) набором 2 вместо набора 1 по умолчанию: ключ Argon2id на 256 МиБ со свёрткой через перец и XChaCha20-Poly1305 кадрами по 64 КиБ, так что файл - шум с первого байта, без даже того узора длины по кластерам в 512 байт, который есть у набора 1. Настоящее имя, реальный размер и время шифрования сохраняются, а собственные отметки времени оригинала - нет: восстановленный файл получает текущее время. Открывает его только FileDO начиная с этой версии - старые сборки FileDO сообщат о повреждении или неверном пароле, а приложения FastMediaSorter его не откроют, поэтому по умолчанию остаётся набор 1. unsecure, reveal, fdsec info и fdsec verify определяют набор сами; больше ничего не меняется, и пустой пароль по-прежнему лишь маскировка.secure suite2 запечатує один файл (не теку) набором 2 замість типового набору 1: ключ Argon2id на 256 МіБ зі згорткою через перець і XChaCha20-Poly1305 кадрами по 64 КіБ, тож файл - шум із першого байта, без навіть того візерунка довжини за кластерами в 512 байт, який має набір 1. Справжнє ім'я, реальний розмір і час шифрування зберігаються, а власні позначки часу оригіналу - ні: відновлений файл отримує поточний час. Відкриває його лише FileDO починаючи з цієї версії - старі збірки FileDO повідомлять про пошкодження чи хибний пароль, а застосунки FastMediaSorter його не відкриють, тому типовим лишається набір 1. unsecure, reveal, fdsec info і fdsec verify визначають набір самі; більше нічого не змінюється, і порожній пароль, як і раніше, лише маскування.

What is promised, and what is notЧто обещано, а что нетЩо обіцяно, а що ні

An empty passwordПустой парольПорожній пароль

An empty password is accepted, and it means obfuscation only - no secrecy: anyone who knows the format opens that file. A short password is not much better. There is no recovery key: a forgotten password is a lost file.Пустой пароль принимается - и означает только маскировку, без секретности: такой файл откроет любой, кто знает формат. Короткий пароль защищает ненамного лучше. Ключа восстановления нет: забытый пароль - это потерянный файл.Порожній пароль приймається - і означає лише маскування, без таємниці: такий файл відкриє будь-хто, хто знає формат. Короткий пароль захищає ненабагато краще. Ключа відновлення немає: забутий пароль - це втрачений файл.

Wiping the originalЗатирание оригиналаЗатирання оригіналу

secure del removes the original in a way any undelete tool can reverse. secure wipe overwrites it first - that lowers the odds of recovery and promises nothing on SSDs, on copy-on-write and on journaled file systems, where overwriting in place does not guarantee the old blocks are gone. By default the original is simply kept.secure del убирает оригинал так, что его вернёт любая программа восстановления. secure wipe сначала затирает его - это снижает шансы на восстановление и ничего не обещает на SSD, на файловых системах с копированием при записи и на журналируемых дисках, где перезапись на месте не гарантирует, что старые блоки исчезли. По умолчанию оригинал просто остаётся.secure del прибирає оригінал так, що його поверне будь-яка програма відновлення. secure wipe спершу затирає його - це знижує шанси на відновлення і нічого не обіцяє на SSD, на файлових системах із копіюванням під час запису та на журнальованих дисках, де перезапис на місці не гарантує, що старі блоки зникли. За замовчуванням оригінал просто залишається.

Where a revealed copy livesГде живёт открытая копияДе живе відкрита копія

In %LOCALAPPDATA%\FileDO\reveal, read-only and readable by this account alone. The copy goes when you say so - the "Remove the copy now" button in the window, or Enter in the console - or when the program that opened it lets go. If the machine loses power, the copy stays until the next FileDO start, which sweeps it; nothing else will. Executables and scripts are never launched out of a container: they are extracted and their location shown.В %LOCALAPPDATA%\FileDO\reveal, только для чтения и только для этой учётной записи. Копия убирается, когда вы скажете - кнопкой «Убрать копию сейчас» в окне или нажатием Enter в консоли, - или когда её отпустит открывшая её программа. Если машина потеряла питание, копия останется до следующего запуска FileDO, который её подметает; больше её не уберёт ничто. Программы и скрипты из контейнера никогда не запускаются: они извлекаются, и показывается их место.У %LOCALAPPDATA%\FileDO\reveal, лише для читання й лише для цього облікового запису. Копія зникає, коли ви скажете - кнопкою «Прибрати копію зараз» у вікні або натисканням Enter у консолі, - або коли її відпустить програма, що її відкрила. Якщо машина втратила живлення, копія залишиться до наступного запуску FileDO, який її прибирає; більше її не прибере ніщо. Програми та скрипти з контейнера ніколи не запускаються: їх видобувають і показують їхнє місце.

The password and the logПароль и журналПароль і журнал

In the window the password is masked and handed to filedo.exe out of sight: it is on no command line, in no run report and in no history.json. On the command line the p:password form is visible in the process list - for scripts there are pf: (a file), pe: (an environment variable) and k: (a key file). The sealed true name is never written to the log either.В окне пароль скрыт и передаётся filedo.exe незаметно: его нет ни в командной строке, ни в отчёте о запуске, ни в history.json. В командной строке форма p:пароль видна в списке процессов - для скриптов есть pf: (файл), pe: (переменная окружения) и k: (файл-ключ). Запечатанное настоящее имя в журнал тоже не пишется.У вікні пароль прихований і передається filedo.exe непомітно: його немає ні в командному рядку, ні у звіті про запуск, ні в history.json. У командному рядку форма p:пароль видна в списку процесів - для скриптів є pf: (файл), pe: (змінна середовища) і k: (файл-ключ). Запечатане справжнє ім'я до журналу теж не потрапляє.

The double-click and the Explorer menuДвойной клик и меню ПроводникаПодвійний клік і меню Провідника

The installer offers the Explorer integration as a component you can switch off. In the builds with no installer - winget, ZIP, go install - one command turns it on. A double-click on a .fd-sec is exactly the "Unsecure and start" menu entry: a console opens, asks for the password there, the file is restored under its true name into %LOCALAPPDATA%\FileDO\reveal, where only you and the system can read it, and handed straight to its ordinary program - the same way an ordinary double-click on any other file would. The copy is removed when you close that console window; if the program still has the file open, the next FileDO start removes it. The container itself is left in place. On Windows 11 the "File DO.." group lives under "Show more options". The Microsoft Store build has no menu entries, but it does claim the .fd-sec type: a double-click opens the FileDO window on its "Open a secret file" page with that container already chosen, and the password is asked there.Установщик предлагает интеграцию с Проводником как отдельный компонент, который можно снять. В сборках без установщика - winget, ZIP, go install - её включают командой. Двойной клик по .fd-sec - это ровно пункт меню «Unsecure and start»: открывается консоль, там спрашивается пароль, файл восстанавливается под своим настоящим именем в папку %LOCALAPPDATA%\FileDO\reveal, которую можете читать только вы и система, и сразу передаётся своей обычной программе - тем же способом, каким это делает обычный двойной клик по любому другому файлу. Копия удаляется, когда вы закрываете это окно консоли; если программа всё ещё держит файл открытым, копию уберёт следующий запуск FileDO. Контейнер при этом остаётся на месте. В Windows 11 группа «File DO..» живёт в «Показать дополнительные параметры». В сборке из Microsoft Store пунктов меню нет, но тип .fd-sec она назначает: двойной клик открывает окно FileDO на странице «Открыть секретный файл» с уже выбранным контейнером, и пароль спрашивается там.Інсталятор пропонує інтеграцію з Провідником як окремий компонент, який можна зняти. У збірках без інсталятора - winget, ZIP, go install - її вмикають командою. Подвійний клік на .fd-sec - це рівно пункт меню «Unsecure and start»: відкривається консоль, там запитується пароль, файл відновлюється під своїм справжнім ім'ям у теку %LOCALAPPDATA%\FileDO\reveal, яку можете читати лише ви та система, і одразу передається своїй звичайній програмі - так само, як це робить звичайний подвійний клік на будь-якому іншому файлі. Копія видаляється, коли ви закриваєте це вікно консолі; якщо програма ще тримає файл відкритим, копію прибере наступний запуск FileDO. Контейнер лишається на місці. У Windows 11 група «File DO..» живе в «Показати додаткові параметри». У збірці з Microsoft Store пунктів меню немає, але тип .fd-sec вона призначає: подвійний клік відкриває вікно FileDO на сторінці «Відкрити секретний файл» з уже вибраним контейнером, і пароль запитується там.

A folder in one backup fileПапка в одном файле резервной копииТека в одному файлі резервної копії

backup packs a folder, a whole drive or a network share into one plain .zip named after the folder and the time - any zip tool opens it on any computer. Before packing, FileDO reads a sample of the content for at most 10 seconds and picks the compression density itself: photos and videos are stored as they are, text is packed tighter, and the chosen level is printed. sec seals that zip into a .fd-sec container behind a password, with the same password rules as above. restore rebuilds the folder beside the archive, or at the address to names.backup упаковывает папку, целый диск или сетевую папку в один обычный .zip, названный по папке и времени, - его откроет любая программа для zip на любом компьютере. Перед упаковкой FileDO не дольше 10 секунд читает образец содержимого и сам выбирает плотность сжатия: фото и видео сохраняются как есть, текст сжимается сильнее, а выбранный уровень печатается. sec запечатывает этот zip в контейнер .fd-sec под паролем, с теми же правилами пароля, что выше. restore восстанавливает папку рядом с архивом или по адресу, который назван в to.backup пакує теку, цілий диск або мережеву теку в один звичайний .zip, названий за текою та часом, - його відкриє будь-яка програма для zip на будь-якому комп'ютері. Перед пакуванням FileDO не довше 10 секунд читає зразок вмісту й сам обирає щільність стиснення: фото й відео зберігаються як є, текст стискається сильніше, а обраний рівень друкується. sec запечатує цей zip у контейнер .fd-sec під паролем, з тими самими правилами пароля, що вище. restore відновлює теку поруч з архівом або за адресою, яку названо в to.

filedo backup D:\Photos sec
filedo restore Photos-2611101530.fd-sec to D:\

The zip records the folder's name, never its path. An existing folder is never merged into or replaced - restore writes beside it as <name>-1 - and an archive whose names would leave the destination is refused whole, before anything is written. The Windows drive itself is refused; a junction or symbolic link in the source refuses the backup unless skip-links leaves it out and lists it. Permissions, alternate data streams and links are not carried. A backup is one whole copy, made when you run it: there is no schedule and no history of earlier backups.Zip хранит имя папки, но никогда не её путь. Существующая папка никогда не дополняется и не заменяется - restore пишет рядом под именем <имя>-1, - а архив, имена внутри которого вывели бы за пределы места назначения, отклоняется целиком, до того как что-либо записано. Диск Windows отклоняется; точка соединения или символическая ссылка в источнике отклоняет копию, если skip-links не оставит её в стороне и не внесёт в список. Права доступа, альтернативные потоки данных и ссылки не переносятся. Резервная копия - одна целая копия, сделанная, когда вы её запускаете: нет расписания и нет истории прежних копий.Zip зберігає ім'я теки, але ніколи не її шлях. Наявна тека ніколи не доповнюється й не замінюється - restore пише поруч під ім'ям <ім'я>-1, - а архів, імена всередині якого вивели б за межі місця призначення, відхиляється цілком, перш ніж щось записано. Диск Windows відхиляється; точка з'єднання або символічне посилання в джерелі відхиляє копію, якщо skip-links не лишить його осторонь і не внесе до переліку. Права доступу, альтернативні потоки даних і посилання не переносяться. Резервна копія - одна ціла копія, зроблена, коли ви її запускаєте: немає розкладу й немає історії попередніх копій.
