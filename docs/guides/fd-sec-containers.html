Руководство · секретные файлыGuide · secret filesПосібник · секретні файли

Один файл, один контейнер, один пароль - и честный рассказ о том, что это даёт.One file, one container, one password - and a straight account of what that buys.Один файл, один контейнер, один пароль - і чесна розповідь про те, що це дає.

FileDO упаковывает файл в контейнер .fd-sec, возвращает его обратно и умеет открыть содержимое в нужной программе, не распаковывая. Настоящее имя, размер и отметки времени запечатаны внутри; снаружи виден только размер самого контейнера.FileDO packs a file into a .fd-sec container, brings it back, and can open what is inside in the program it belongs to without unpacking it. The true name, the size and the timestamps are sealed inside; from outside only the container's own size is visible.FileDO пакує файл у контейнер .fd-sec, повертає його назад і вміє відкрити вміст у потрібній програмі, не розпаковуючи. Справжнє ім'я, розмір і позначки часу запечатані всередині; ззовні видно лише розмір самого контейнера.

Три операцииThree operationsТри операції

Всё остальное - подробности этих трёх. Они доступны из командной строки, из группы «File DO..» в контекстном меню Проводника и со страниц группы «Защита» в окне программы.Everything else is detail on these three. Each is available from the command line, from the "File DO.." group in the Explorer context menu, and from the Protect pages in the program's window.Усе інше - подробиці цих трьох. Вони доступні з командного рядка, з групи «File DO..» в контекстному меню Провідника та зі сторінок групи «Захист» у вікні програми.

УпаковатьPackЗапакувати

Рядом с файлом появляется report.fd-sec. Пароль спрашивается дважды и не отображается. Оригинал остаётся на месте, пока вы не попросите его убрать.A report.fd-sec appears beside the file. The password is asked for twice and never echoed. The original stays where it is until you ask for it to go.Поруч із файлом з'являється report.fd-sec. Пароль запитується двічі й не відображається. Оригінал залишається на місці, доки ви не попросите його прибрати.

filedo report.docx secure

Вернуть оригиналGet the original backПовернути оригінал

Файл возвращается под своим запечатанным именем и со своими отметками времени. Существующий файл никогда не перезаписывается молча.The file comes back under its sealed name and with its own timestamps. An existing file is never overwritten silently.Файл повертається під своїм запечатаним іменем і зі своїми позначками часу. Наявний файл ніколи не перезаписується мовчки.

filedo report.fd-sec unsecure

Открыть, не распаковываяOpen without unpackingВідкрити, не розпаковуючи

Содержимое открывается в той программе, которой оно принадлежит - из временной копии, которая потом убирается. Команда набирается вручную; двойной клик по контейнеру делает другое - см. ниже.The content opens in the program it belongs to, from a temporary copy that is taken away again. This one is typed by hand; a double-click on the container does something else - see below.Вміст відкривається в тій програмі, якій він належить - із тимчасової копії, яку потім прибирають. Цю команду набирають вручну; подвійний клік на контейнері робить інше - див. нижче.

filedo report.fd-sec reveal

Что обещано, а что нетWhat is promised, and what is notЩо обіцяно, а що ні

Пустой парольAn empty passwordПорожній пароль

Пустой пароль принимается - и означает только маскировку, без секретности: такой файл откроет любой, у кого есть FileDO. Короткий пароль защищает ненамного лучше. Ключа восстановления нет: забытый пароль - это потерянный файл.An empty password is accepted, and it means obfuscation only - no secrecy: anyone with FileDO opens that file. A short password is not much better. There is no recovery key: a forgotten password is a lost file.Порожній пароль приймається - і означає лише маскування, без таємниці: такий файл відкриє будь-хто, у кого є FileDO. Короткий пароль захищає ненабагато краще. Ключа відновлення немає: забутий пароль - це втрачений файл.

Затирание оригиналаWiping the originalЗатирання оригіналу

secure del убирает оригинал так, что его вернёт любая программа восстановления. secure wipe сначала затирает его - это снижает шансы на восстановление и ничего не обещает на SSD, на файловых системах с копированием при записи и на журналируемых дисках, где перезапись на месте не гарантирует, что старые блоки исчезли. По умолчанию оригинал просто остаётся.secure del removes the original in a way any undelete tool can reverse. secure wipe overwrites it first - that lowers the odds of recovery and promises nothing on SSDs, on copy-on-write and on journaled file systems, where overwriting in place does not guarantee the old blocks are gone. By default the original is simply kept.secure del прибирає оригінал так, що його поверне будь-яка програма відновлення. secure wipe спершу затирає його - це знижує шанси на відновлення і нічого не обіцяє на SSD, на файлових системах із копіюванням під час запису та на журнальованих дисках, де перезапис на місці не гарантує, що старі блоки зникли. За замовчуванням оригінал просто залишається.

Где живёт открытая копияWhere a revealed copy livesДе живе відкрита копія

В %LOCALAPPDATA%\FileDO\reveal, только для чтения и только для этой учётной записи. Копия убирается, когда вы скажете - кнопкой «Убрать копию сейчас» в окне или нажатием Enter в консоли, - или когда её отпустит открывшая её программа. Если машина потеряла питание, копия останется до следующего запуска FileDO, который её подметает; больше её не уберёт ничто. Программы и скрипты из контейнера никогда не запускаются: они извлекаются, и показывается их место.In %LOCALAPPDATA%\FileDO\reveal, read-only and readable by this account alone. The copy goes when you say so - the "Remove the copy now" button in the window, or Enter in the console - or when the program that opened it lets go. If the machine loses power, the copy stays until the next FileDO start, which sweeps it; nothing else will. Executables and scripts are never launched out of a container: they are extracted and their location shown.У %LOCALAPPDATA%\FileDO\reveal, лише для читання й лише для цього облікового запису. Копія зникає, коли ви скажете - кнопкою «Прибрати копію зараз» у вікні або натисканням Enter у консолі, - або коли її відпустить програма, що її відкрила. Якщо машина втратила живлення, копія залишиться до наступного запуску FileDO, який її прибирає; більше її не прибере ніщо. Програми та скрипти з контейнера ніколи не запускаються: їх видобувають і показують їхнє місце.

Пароль и журналThe password and the logПароль і журнал

В окне пароль скрыт и передаётся filedo.exe незаметно: его нет ни в командной строке, ни в отчёте о запуске, ни в history.json. В командной строке форма p:пароль видна в списке процессов - для скриптов есть pf: (файл), pe: (переменная окружения) и k: (файл-ключ). Запечатанное настоящее имя в журнал тоже не пишется.In the window the password is masked and handed to filedo.exe out of sight: it is on no command line, in no run report and in no history.json. On the command line the p:password form is visible in the process list - for scripts there are pf: (a file), pe: (an environment variable) and k: (a key file). The sealed true name is never written to the log either.У вікні пароль прихований і передається filedo.exe непомітно: його немає ні в командному рядку, ні у звіті про запуск, ні в history.json. У командному рядку форма p:пароль видна в списку процесів - для скриптів є pf: (файл), pe: (змінна середовища) і k: (файл-ключ). Запечатане справжнє ім'я до журналу теж не потрапляє.

Двойной клик и меню ПроводникаThe double-click and the Explorer menuПодвійний клік і меню Провідника

Установщик предлагает интеграцию с Проводником как отдельный компонент, который можно снять. В сборках без установщика - winget, ZIP, go install - её включают командой. Двойной клик по .fd-sec - это ровно пункт меню «Unsecure and start»: открывается консоль, там спрашивается пароль, файл восстанавливается под своим настоящим именем в папку %LOCALAPPDATA%\FileDO\reveal, которую можете читать только вы и система, и сразу передаётся своей обычной программе - тем же способом, каким это делает обычный двойной клик по любому другому файлу. Копия удаляется, когда вы закрываете это окно консоли; если программа всё ещё держит файл открытым, копию уберёт следующий запуск FileDO. Контейнер при этом остаётся на месте. В Windows 11 группа «File DO..» живёт в «Показать дополнительные параметры».The installer offers the Explorer integration as a component you can switch off. In the builds with no installer - winget, ZIP, go install - one command turns it on. A double-click on a .fd-sec is exactly the "Unsecure and start" menu entry: a console opens, asks for the password there, the file is restored under its true name into %LOCALAPPDATA%\FileDO\reveal, where only you and the system can read it, and handed straight to its ordinary program - the same way an ordinary double-click on any other file would. The copy is removed when you close that console window; if the program still has the file open, the next FileDO start removes it. The container itself is left in place. On Windows 11 the "File DO.." group lives under "Show more options".Інсталятор пропонує інтеграцію з Провідником як окремий компонент, який можна зняти. У збірках без інсталятора - winget, ZIP, go install - її вмикають командою. Подвійний клік на .fd-sec - це рівно пункт меню «Unsecure and start»: відкривається консоль, там запитується пароль, файл відновлюється під своїм справжнім ім'ям у теку %LOCALAPPDATA%\FileDO\reveal, яку можете читати лише ви та система, і одразу передається своїй звичайній програмі - так само, як це робить звичайний подвійний клік на будь-якому іншому файлі. Копія видаляється, коли ви закриваєте це вікно консолі; якщо програма ще тримає файл відкритим, копію прибере наступний запуск FileDO. Контейнер лишається на місці. У Windows 11 група «File DO..» живе в «Показати додаткові параметри».
